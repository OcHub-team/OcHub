# OcHub console design · 2026-10-13

状态：可交互设计稿；生产实现以真实 DTO 与能力为准。`index.html` 可直接本地打开，不加载远端脚本、字体或数据。所有数据、示例名称、通知和写入动作均为虚构演示，不连接真实环境。

## 核心取舍

OcHub 的中心任务是明确指定环境中，哪个应用使用哪条连接、配置允许请求走向哪里、出现问题后从哪里继续。新的视觉体系围绕这些对象组织，不先要求用户理解内部 Rust 模块，也不把大量数值卡片当作总览。

推荐保留 GPUI 原生实现，统一共享的排版、间距、控件、表格、导航与详情面板；不把换成网页容器当作视觉改善的前提。浏览器组件体系只作为交互与一致性参考，不宣称某个库具有经过验证的流行度排名。

主导航为总览、连接、路由、记录与用量、扩展、设置。常用应用保留直达；生产侧栏使用可折叠应用列表，系统与通知保留固定入口。环境切换器始终位于标题栏，连接、路由、用量、扩展写入均属于所选环境；外观与窗口偏好属于本机。

| 入口 | 首要内容 | 次级入口与边界 |
| --- | --- | --- |
| 总览 | 当前配置路径、读取状态、需处理的事实、近期记录 | 用量趋势辅助判断；不显示没有证据的全局健康分数 |
| 连接 | 应用与连接、草稿、写入状态 | 常用 / 高级 / 文件工作台保持原有分层，保存与应用分离 |
| 路由 | 模型规则、应用关联、候选上游及优先级 | 点击检查配置；不把配置连接线冒充某次请求轨迹 |
| 记录与用量 | 请求、会话、用量三种视角 | 来源明确；费用是定价估算；会话没有可靠请求耗时 |
| 扩展 | 应用插件、MCP、技能 | 三种生命周期保留；安装、固定侧栏和写入不是一个大开关 |
| 设置 | 本机外观与目标环境配置分开 | 完整维护能力保留，不放入无边界的工具杂物页 |

## 页面与交互

总览上半部是可选择的连接行与配置路径，使用虚线表示关联。选中应用后显示目标应用、直连接入或网关路由、候选上游；节点内容始终可读，不使用移动粒子表达未经采集的流量。下半部使用一行简洁数值、真实时间桶趋势与近期记录；不重复相同的 KPI 卡片。

抽屉用于不离开当前位置的只读检查。1280 与宽窗口仍采用右侧覆盖详情，960 不强行挤成三栏；详细编辑继续使用完整工作台。窄窗口保留列的语义和水平滚动，不通过隐藏重要状态制造“看上去更简洁”。抽屉、通知与配置详情均有关闭按钮、Escape 与焦点约束。

`index.html` 支持实际交互：

- 环境切换：本机、开发机、离线工作站；离线显示读取不可用，而不是全零统计。
- 时间窗：24 小时、7 天、30 天，示例时间桶和数值跟随变化。
- 主导航与常用应用筛选、全局文本搜索、路由选择、请求详情。
- 浅色 / 深色、标准 / 紧凑密度、960 / 1280 / 宽视口。
- 短成功、长错误、应用结果未知三类通知；完整详情、复制、已读与同一任务核对。
- 演示草稿只保存在页面内，不调用真实存储或配置接口。

## 通知作为一套行为

第一层是原位状态：字段错误、配置检查、当前工作台保存与应用结果留在原位。避免同一句操作结果同时弹 toast 与占用 inline 区域。

第二层是短暂通知：短标题、一行必要上下文、最多一个“详情”等动作，以及关闭按钮。默认位于全局工具栏下方的右上角，避开编辑器底部保存栏。浮层不完整展示原始错误；悬停或聚焦时暂停消失。页面可设置安全偏移，但不随着导航无理由改变位置。

第三层是本次启动的通知中心：完整说明、环境、时间、未读状态、必要的技术详情与复制。现有历史是内存列表，不承诺跨启动持久化或审计完整性。关闭 / 已读不等于解决；未读数与需处理事项是不同统计。请求流水留在记录页，不能每个请求都挤进通知中心。

动作必须保留原始环境与对象。远端应用结果未知只提供“核对同一次提交”，不能直接重试最新输入；撤回只在具备真实回执和适用环境时出现。通知数据进入历史前应去除密钥、token 与敏感原文，不把技术详情当作未审查的日志转储。

## 视觉契约

方向是安静、可比较的桌面控制台：暖中性浅色、炭灰深色、单一蓝色强调；蓝色表示当前选中和主动作，状态额外使用文字或符号。使用平台可用的清晰无衬线字体，避免下载字体造成原生启动与跨平台回退差异。

| 元素 | 规格 |
| --- | --- |
| 正文 / 辅助 / 区标题 / 页标题 | 13/20、12/18、15/22、24/30 |
| 间距 | 4、8、12、16、24、32 |
| 主要控件 | 32 高；焦点边界可见 |
| 标准 / 紧凑表格行 | 44 / 36；交互控件不随行缩到不可点击 |
| 圆角 | 控件 6、独立面板 8、浮层 10 |
| 阴影 | 仅浮层、详情；不为每个普通区块加阴影 |
| 侧栏 | 原型与生产均按约 220，并允许折叠长应用列表 |
| 通知 | 360 宽，距右侧 16，顶部在全局工具栏下方；详情 400 最大宽 |
| 内容留白 | 通常 24，960 宽为 20；正文区域可滚动 |

## 真实数据映射与不可承诺项

采用 `Application::overview_snapshot(from, to)` 的独立分区返回结构。`gateway`、`routing`、`apps`、`usage`、`trend`、`performance`、`recent_requests` 可以分别失败；不能因为一个失败清空或假装其余成功，也不能将失败映射为 0。

| UI 信息 | 真实数据来源 | 约束 |
| --- | --- | --- |
| 网关运行 | `GatewayStatus.running/port/base_url` | 仅监听服务状态，不等于模型可用或客户端采用配置 |
| 配置路径 | 应用连接的 `gateway_route_id` → `GatewayRoute` → 候选 channel | 关联缺失显示“未关联”；不能由无关联直接推断直连 |
| 路由规则 | `GatewayRoute.model_rules/channel_ids`、channel 优先级与权重 | 空 `channel_ids` 表示所有允许启用接口，不是零候选 |
| 接口可达性 | `ChannelHealth` 映射的缓存状态 | 无采样时间；401/403 也可证明可达；不是健康/SLA |
| 已记录用量 | 去重后的 `UsageSummary` | 同时包括网关与导入会话；费用是估算 USD |
| 性能 | `performance` 名称与来源分组 | 仅最多 20 组，不能重新汇总当作全量来源统计；不按名称连回路由 ID |
| 近期请求 | 安全投影后的最近 10 条记录 | 总览显示记录模型；客户端请求别名从完整记录详情查看；会话耗时为未知；没有历史逐跳路由追踪 |
| 趋势 | UTC 窗口与 hour/day 时间桶 | 显示节点时区，不混用本机时区；不凭平均值画 P95 |

首轮生产总览只读取数据，不主动 probe、同步会话、创建网关 key 或产生配置写入。环境切换和请求 generation 共同阻止旧回包覆盖新页面。不存在的远端 capability 给出升级 / 不支持状态，不降级执行本地操作。

## 两轮评审

第一轮与共享 UI、core 两个代理达成：总览以路径和问题为中心，普通区块使用行与分隔线；通知中心明确“本次启动”；配置与实际请求分开；引用已有真实数据并保持远端边界。

第二轮共享 UI 代理复核已通过；原型侧栏统一为 220，避免借更窄侧栏掩盖 960 布局问题。原型计时在离开悬停后重新计时，仅供演示；生产保存剩余时长。全局密度开关仅作为设计比较，生产首期由页面选择标准或紧凑 tokens，不上线不完整的全局偏好。第二轮重点审核：960 不出现三栏硬挤，通知不盖固定保存栏，原始错误不挤进短标题，读/关通知不解决问题，历史动作绑定原环境，网关运行与可达性不被写成健康，以及会话费用与时序不伪造。原型可视与生产的进一步差异以代码验收结果记录，不能将此演示当成已完成全平台实测。

## 实现顺序

1. 共享视觉 tokens、导航/表格/检查器及结构化通知向后兼容升级。
2. 接入真实只读总览与分区错误、时间窗、环境隔离；导航放置总览与应用直达。
3. 将现有页面逐步使用共享视觉契约，保持配置能力与安全语义。
4. 固定 QA 包检查 960 / 1280、浅深色、长应用名、错误、断线和通知；Windows/Linux 仍需真实平台验收，不能仅凭 macOS 的截图宣布完成。

暂不增加插件市场、云账号、新的逐请求 trace 存储、自动联网检查或强制所有流量走网关。这些属于新的能力，不是本轮视觉与信息结构重塑的隐含前提。
