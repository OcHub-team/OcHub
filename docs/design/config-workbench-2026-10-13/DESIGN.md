# 配置工作台设计稿 · 第二轮评审

日期：2026-10-13。类型：开发设计资料，不是产品功能文档。原型入口：[index.html](index.html)。

## 目标与交付边界

让常用配置保持短路径，让完整配置能力按需出现；最先解决“输入是否保留、保存会不会写应用、错误后还能做什么”三个信任问题。沿用当前原生桌面应用的暖中性底色、Helvetica 字体、紧凑边界和蓝色主动作，不引入新的视觉品牌或强制向导。

本原型只使用虚构数据和页面内存，不读取、写入、上传任何配置，不发送网络请求。场景选择器在模拟应用窗口外，属于评审工具。原型的流程演示不等于已经存在相应后端能力；生产实现必须通过下述契约验收。

第一批实现范围是连接的编辑、配置检查、保存、明确写入与离开保护。全局信息架构、来源数据库合并、插件市场、跨环境共享密钥和多层默认继承均不属于本批次。原型侧栏仅提供上下文及导航保护演示，不要求同步重排所有导航。

## 两轮评审后的决策

| 议题 | 最终选择 | 原因及限制 |
|---|---|---|
| 页面结构 | 单页持续编辑，常用 / 高级 / 配置文件三个深度入口 | 支持局部修改和反复检查，不为熟练用户增加向导页 |
| 主动作 | 固定底部单一主动作，根据能力显示应用、加入或外部导入 | 切换、叠加、外部导入有不同结果，不能统一伪装成启用 |
| 保存 | 次要“保存到 OcHub”，保存独立 EditorDraft，成功留在编辑器 | 允许未完成或无效字段、原始文本；live 文件、正式 provider 和当前身份不变 |
| 自动编辑状态 | 与 providers 记录隔离，使用编辑草稿与版本 CAS | 避免无效中间态、未确认密钥或仅键入字符覆盖真实连接记录 |
| 高级能力 | 尊重所有 codec 的 schema advanced，保留已设置项提示 | 取消当前仅 Codex 折叠的特例；收起不等于关闭 |
| 原始配置 | 文本编辑合入当前编辑内容，明确“更新编辑内容” | 避免把内存合并与实际应用操作都叫“应用” |
| 公共片段 | 明确“共享内容＋实际覆盖规则” | 现有通用片段会覆盖连接值，不能以“继承默认值”包装实际行为 |
| 未知字段与格式 | 保留 manifest 与 codec 未建模键；格式、注释按能力说明 | JSON Value 无法兑现任意注释的字节级往返保证 |
| 远程能力 | 协商能力；缺失时禁用仅保存，解释真实后果 | 不从 APP_SCHEMA 拼装未知远端 codec，不回退本机，不以普通 update 假装草稿 |
| 撤回 | 仅完整 ApplyReceipt 能提供入口 | 要有精确 before、after 指纹、环境及对象身份，不能用漂移 Revert 冒充操作撤销 |

## 页面与行为

960 × 640：侧栏与工作台同屏；标题、三层入口、底部动作始终可见；只有编辑区域纵向滚动。配置文件替换表单视图，不在小窗口中强挤并排预览。

1280 × 800：保持同一动作与焦点模型，增加字段间距、原始编辑高度和阅读宽度；不因窗口变宽把低频动作全部铺开。若后续确有双栏需求，可增加用户主动打开的对照预览，不能将宽窗口自动挤压表单作为默认。

默认常用字段只包含目标应用支持且完成接入必要的参数。高级字段可以完整配置，切换深度、来源或应用语言不得重建并清空输入。原型 API / 官方模式往返保留 API 字段，体现此规则；正式来源模型需维护对应分支的草稿。

页内只保留一个写入主动作。检查与保存是次要按钮。帮助、复制到其他应用、查看关联来源为低频辅助动作。高级数量来源于实际非默认设置；字段验证失败时应展开其所在分区并聚焦，不能留下一个隐藏错误阻止提交。

## 状态与动作契约

### 保存不是写入

“保存到 OcHub”保存独立 EditorDraft，包括尚未填完或无效的字段、未合入的原始文本。目标文件、正式 provider 记录、当前连接指针和 live 管理身份均不变。成功后留在编辑器，显示草稿已保存。连接列表提供独立草稿入口，不把草稿误标为可使用的正式连接。Cmd/Ctrl+S 始终保存编辑草稿，原始文本不需要先通过格式校验，更不能偷偷触发目标写入。

如果草稿保存成功而后续应用失败，显示两部分事实：草稿已保存；目标配置未写入，或者目标结果未知。正式 providers 仅在应用成功后提交。用户能重试应用并保持相同草稿与连接身份，不能重复生成新增记录。

当前源码对 Codex 和其他应用的保存行为不同。生产实现需先扩展通用草稿契约、同步本地/远程协议与能力协商，随后才能普遍使用“保存到 OcHub”按钮。

第二轮确认的数据接口：`EditorDraftInput { provider, original_provider_id, base_provider_hash, editor_state, raw_documents? }`；`EditorDraft { app, id, revision, updated_at, input }`。保存使用 expected revision 做 CAS。应用读取用户确认的同一 revision，经目标 codec 验证和准备文件计划后执行，防止后台编辑覆盖正在应用的内容。若有 `raw_documents`，core 必须重新解析它们，不能应用旧的已解析 provider 而忽略用户最新原文。编辑 UI 不以 `provider` 字段的存在推断草稿已经进入正式 providers 表。

### 检查不是账号验证

配置检查负责语法、必填和可本地确认的约束。网络测试必须明确目标和方法，由用户触发。配置输入变化后旧检查结果失效；结果绑定编辑版本，迟到响应不能覆盖新的输入状态。

### 写入不是客户端已经读取

文件写入成功后可以陈述已写入具体目标；是否被客户端读取要使用“需重启 / 等待应用内确认 / 无法自动确认”。不以绿色状态暗示模型请求已经成功。官方账号仍通过目标应用登录，不把登录令牌当作可跨应用复制的 API key。

### 草稿导航与关闭

统一处理侧栏、目标应用、应用设置、环境切换、返回/取消、Esc、Cmd/Ctrl+W 和窗口关闭。没有修改可直接离开。有修改时提供继续编辑、放弃修改、保存并离开；保存允许未完成或格式无效的编辑内容。存储失败或草稿 revision 冲突则留在编辑器并指出原因。忙碌操作保留任务和结果归属，不能随视图销毁丢失。

Dirty 快照包含来源、字段、名称、备注、通用片段及未合入原始文本，不使用预览缓存 dirty 标志。草稿已保存后仍未完成的字段不应导致重复离开警告；判断依据是相对已保存草稿的变化。自动恢复必须使用独立状态存储和明确密钥保护，不能每次输入覆盖 providers。

### 外部冲突与撤回

应用前核对 live 基线。有外部变化则阻止并展示差异，不默认覆盖。撤回需要操作回执，包含环境、应用、provider、变更路径、before 内容、after 指纹、当前身份变化和时间。仅当当前对象仍匹配本次 after 指纹，才能恢复对应 before。

叠加模式不能恢复整份旧文件而覆盖其他连接的新变化。最小安全实现采用整文件 after 指纹 CAS：其他 provider 在应用后产生任何新变化，就拒绝撤回并说明原因；本批次不承诺语义级局部反向合并。外部导入和未具备完整回执的官方登录路径不显示伪造的一键撤回。`ExternalConfirmation` 保留草稿，不声明正式 provider 已提交或客户端已经应用。多文件部分失败、恢复失败和远程结果未知均需独立报告。

## 原型场景

| 场景 | 体验路径 | 需要表达的事实 |
|---|---|---|
| API / 完整回执 | 修改 → 检查 → 保存 → 应用 → 回执 → 撤回 | 保存与写入分离，撤回有基线 |
| 必填错误 | 应用 → 字段定位 → 可先保存草稿离开 → 继续修正 | 无效输入可持久保存；只有应用需通过配置校验 |
| 写入失败 | 应用 → 草稿已保存但目录不可写 → 重试 | 部分完成真实可见，正式连接未提交 |
| 外部冲突 | 应用 → 阻止 → 查看差异 → 继续编辑 | 不自动覆盖外部变化 |
| 无回执 | 应用 → 已写入但无撤回入口 | 不用假按钮承诺不能兑现的恢复 |
| 官方登录 | 登录方式 → 说明 → 写入配置 | 登录由目标工具完成，状态不虚构 |
| Cherry 导入 | 保存 → 发出导入请求 → 等待应用确认 | 不把请求已发送当成导入已接受 |
| 旧远端 | 保存与应用均禁用，提示升级节点 | 不以普通 update 冒充独立草稿保存，不做隐式直接写入 |
| 导航 | 修改 → 点击侧栏 / Esc → 离开保护 | 同一决策覆盖所有出口 |

## 生产模块建议

- `provider_editor.rs`：编辑内容快照、真实操作状态、通用高级折叠、来源分支草稿、保存/应用命令、检查定位、原始编辑文案。
- `product_ui/provider_editor.rs`：页内深度导航、固定动作栏、内容滚动边界和状态摘要。维持独立 UI 库的组件归属。
- `app_ui.rs`：统一 PendingNavigation、关闭/环境切换保护、结构化完成事件及操作归属。
- core `application/providers.rs`、`services/provider.rs`：通用持久草稿与应用契约，避免保存改 live，结果分阶段；精确撤回是单独能力。
- `remote/backend.rs` 与远程协议：协商保存能力与结构化操作结果，拒绝未知语义降级，防止断线重复创建。
- provider-config 与 managed-app manifests：结构化编辑与未知键保留，字段阶段元数据，明确序列化格式边界。
- 相邻 `ochub-docs`：功能完成后同步三语操作说明，验证并提交。此处不复制用户文档站。

## 必要验收

1. 新增 / 编辑 × 当前 / 非当前 × 切换 / 叠加 / 外部导入 × 本地 / 远端。
2. 保存未完成与无效原始文本后可重新打开；live 文件逐字节不变、正式 providers 与 current 指针不变；应用成功后才提交正式连接。
3. 保存成功应用失败输入仍在，同一草稿可重试；revision 冲突不会覆盖新编辑；多文件状态不能压缩为一个泛化成功提示。
4. 所有导航出口统一保护；Esc 先最内层临时层，再编辑离开判断；模态层正确恢复焦点。
5. 来源往返、基础/高级/源码往返保留凭据与未建模字段；注释不做超出格式能力的承诺。
6. 旧远端草稿能力缺失时禁用真实受限操作，不隐藏调用普通 update。
7. 撤回核对 after 指纹；有外部变化拒绝盲写；叠加模式不覆盖其他 provider。
8. 960 × 640、1280 × 800、三语言、键盘全流程、长 URL/名称/模型和无效原始文本。

## 有意放弃

首批不做强制三步向导、全局导航重组、键入即保存 provider、多层默认继承、无差别绿色“已生效”、后台自动真实模型测试。它们或增加日常步骤，或在契约未完备时模糊后果，与本次“能力强而使用舒服”的目标不符。

## 原型实现限制

原型为无构建依赖的 HTML/CSS/JS，目的是评审尺寸、动作层次与状态文案。语法检查只有最低限度演示，不能用于生产配置验证。配置文本切换、演示撤回和错误是固定场景，真实实现必须调用 codec、计划、回执与文件检查。场景切换会主动重置虚构编辑内容，这属于窗口外评审工具，不是产品导航行为。
