# OcHub 需求重梳与交互改进方案

日期：2026-09-21。分析基线：主仓库 `b8ddca3`，并参照相邻 `ochub-docs` 仓库的现有中文用户文档。

状态：设计提案，尚未实现。本文是开发设计文档，不是用户操作手册。

## 1. 结论与分析边界

OcHub 最重要的任务应当是：**让指定环境里的 AI 工具用上合适的模型来源，并让用户知道配置是否写入、连接是否验证、失败后如何恢复。**

当前问题集中在任务、对象和状态之间的关系：用户想“让 Codex 用这个服务”，界面却要求他先理解应用连接、模型供应商、本地网关、应用设置、网络设置之间的分工。同一个“保存”的后果还会因应用和当前状态不同而变化。这会破坏用户对操作的预测，比单纯的颜色、间距问题更优先。

建议以应用为主要工作入口，以环境为明确边界，以模型来源为可复用资源；把直连、协议转换、网关运行等机制放在连接详情和高级选项中解释。先修复操作语义与状态可信度，再重组导航和页面。

本次证据范围：

- 已检查应用外壳、连接编辑器、供应商、MCP、技能、用量、会话、设置、工具及远程后端的相关实现，并对照用户文档。
- 原生界面检查接口连续超时，未取得可靠的 AX 树或截图。因此，本文没有把字号、对比度、实际遮挡、焦点顺序等视觉判断当作已实测缺陷。
- 用户角色、任务频率及下文时间目标属于设计假设，需要可用性测试验证；没有实际访谈、使用量统计或完成时间基线。
- 原有 `docs/ui-overhaul.md` 是历史改造记录。里面“没有删除确认”等旧问题不能直接作为当前结论；当前已有多种删除确认和冲突处理。

## 2. 当前问题：证据与优先级

优先级定义：P0 影响配置安全、操作结果或信任；P1 阻碍核心任务；P2 影响组织、效率和学习成本。这里的等级是产品改造优先级，不代表已发生事故。

| 编号 | 当前证据 | 用户后果 | 优先级 | 对应方案 |
|---|---|---|---|---|
| E01 | 连接编辑器中，Codex 保存走草稿分支；其他应用走普通更新。普通更新可能改写当前连接或已加入应用的连接；新增也存在自动写入分支 | “保存”无法稳定预测是否改变工具配置 | P0 | 明确区分保存草稿与写入应用，并补齐后端语义 |
| E02 | 切换应用、切换导航及进入应用设置等路径直接清空 `editor`；取消编辑也直接发出关闭事件 | 编辑中离开页面可能丢失未保存输入 | P0 | 统一离开编辑流程，覆盖侧栏、环境切换、返回与关闭 |
| E03 | 当前连接摘要传入固定“直接连接”标签，组件无条件显示；是否网关只改变图标及其他内容 | 网关连接可能被展示成直接连接，状态含义错误 | P0 | 从真实连接类型生成路径描述，类型不用成功色表达 |
| E04 | 停用供应商直接修改启用状态；删除则有引用检查与确认。用户文档明确说明停用在用供应商会使相关请求失败 | 危险性相近的操作保护不一致 | P0 | 停用前展示受影响连接，提供迁移或明确停用动作 |
| E05 | 在连接编辑器选择供应商来源但无可选项时，只显示“去模型供应商页面创建”的文字 | 首次连接流程断开，离开还叠加 E02 | P1 | 在当前流程内创建来源，完成后回填并继续 |
| E06 | 导航按应用、工具、网络、系统组织；应用配置、供应商、代理、诊断工具分属不同页面 | 用户需要按内部模块拼出一条完整任务链 | P1 | 应用页聚合当前连接、验证、诊断和相关设置 |
| E07 | MCP 开关实际立即写入/移除目标应用配置；用户文档仍要求调整后再“同步到应用” | 用户无法确定开关何时生效、同步按钮是否必要 | P1 | 保留即时应用，显示逐应用结果；同步明确为重新写入；同步修正文档 |
| E08 | 连接与供应商使用不同的编辑容器；“保存并启用”及部分高级折叠目前是 Codex 特有路径 | 换工具后需要重新学习完成编辑的方式 | P1 | 统一编辑框架与动作词，字段和能力仍按应用适配 |
| E09 | 用量同时涉及会话和网关数据；直连不具备同样的请求可见性 | 如果只显示总计或“健康”，用户容易高估覆盖范围 | P1 | 明确来源、覆盖范围、估算属性和不可观测状态 |
| E10 | 工作区切换器已经存在；本地界面设置与目标环境设置的作用范围不同 | 远程操作需要额外确认自己正在改哪台机器 | P1 | 页面标题、写入预览、操作结果都携带环境；本机界面设置单独标明 |
| E11 | 启动行为、配置目录、环境变量、CLI 维护、快照等散落在设置、工具与应用设置 | 遇到问题不知道从哪里开始查 | P2 | 诊断按问题组织，设置按作用对象组织，避免重复编辑入口 |

E01—E08 可由相关代码路径或代码与文档差异直接核对。E09—E11 是基于现有能力组织方式提出的风险判断，仍需任务测试评估影响大小。E03 是静态渲染路径结论，尚未实机截图复现。

应保留的基础：现有配置预览、外部配置冲突处理、删除保护、搜索和筛选、列表虚拟化、主题预览恢复、远程能力协商，以及高级路由功能。当前 Codex 的“检查配置”成功文案已经说明账号与服务能力未验证，不应把它误判成虚假联网成功；需要的是让其他流程也具有同样清楚的边界。

## 3. 重新定义需求

### 3.1 用户与任务假设

| 用户情境 | 主要目标 | 默认应该看到 | 按需展开 |
|---|---|---|---|
| 单工具使用者，首要服务对象 | 接入服务、切换连接、恢复可用状态 | 自己的应用、当前配置、下一步操作 | 配置文件、协议、网关参数 |
| 多工具使用者 | 将已有来源用于另一工具，管理共享扩展 | 来源的使用范围、应用能力差异、逐应用结果 | 映射、批量操作、原始配置 |
| 高级路由使用者 | 管理多接口、模型映射、故障转移和成本 | 当前规则及其影响、验证结果 | 完整路由与接口设置 |
| 远程环境管理者 | 在指定机器上完成以上任务 | 环境身份、连接状态、目标路径 | 节点维护、升级、指纹与版本信息 |

这些是任务情境，不应要求用户先选择“新手/专家”模式。一个人可以在不同任务里使用不同深度。

### 3.2 需求清单与完成条件

| ID | 需求 | 用户可确认的完成条件 | 层级 |
|---|---|---|---|
| R01 | 接管已有配置 | 找到现有应用与配置，能预览、跳过、导入；未经写入动作不改变原配置 | 必须 |
| R02 | 首次接入模型来源 | 在一个连续流程内选择应用、填写来源、写入配置、看到验证与重启说明 | 必须 |
| R03 | 切换已存在的连接 | 不重新填写密钥，不重新走向导；知道写入结果，能撤回本次切换 | 必须 |
| R04 | 看懂当前状态 | 能分别回答“存了吗”“写入了吗”“验证了吗”“工具实际读到新配置了吗” | 必须 |
| R05 | 出错后恢复 | 错误有发生位置、受影响目标和下一步；保留已填内容，允许单项重试 | 必须 |
| R06 | 编辑不中断工作 | 导航不会静默丢弃输入；编辑当前连接不会在未明确写入时改变运行配置 | 必须 |
| R07 | 把来源用于另一应用 | 选择目标、确认兼容性与写入影响；成功与失败逐项呈现 | 应该 |
| R08 | 管理 MCP 与技能 | 在目标应用范围内知道安装/写入结果与重启要求 | 应该 |
| R09 | 查询会话、请求与用量 | 搜索和筛选保留；知道数据来自哪里、覆盖什么、哪些费用是估算 | 应该 |
| R10 | 安全操作远程环境 | 所有写入都明确机器与路径；断线后能核对结果，不能盲目重复执行 | 必须 |
| R11 | 高级路由与维护 | 可配置原有高级能力，不干扰常用接入与切换 | 保留并渐进呈现 |
| R12 | 备份与恢复 | 修改前有可定位的恢复点；恢复前能预览影响，遇到新外部修改先处理冲突 | 必须 |

本轮不应新增的范围：全新插件市场、团队权限系统、云端账号体系、自动跨环境复制密钥、强制所有流量走网关。先把现有核心能力组织正确。

## 4. 统一对象与状态含义

### 4.1 面向用户的对象

| 对象 | 用户理解 | 边界 |
|---|---|---|
| 环境 | 正在管理的本机或某台远程机器 | 配置、路径、密钥、运行服务均属于明确环境 |
| 应用 | Codex、Claude Code 等目标工具 | 每个应用有真实的接入、扩展、启动和观测能力 |
| 模型来源 | 官方登录或某个 API 服务 | 官方登录按应用能力保留，不把登录令牌假装成可任意复用的 API Key |
| 连接 | 某个应用如何使用一个来源 | 包含接入方式、适用模型设置及应用配置；同一来源可以有不同应用连接 |
| 接入方式 | 直接连接，或通过 OcHub 网关 | 是连接的属性，用户需要时能看见，不是两套互不相通的任务入口 |
| 扩展 | MCP 服务或技能 | 可以共享入口，但两者的安装、运行与配置生命周期保持独立 |

用户先决定“哪个应用，用哪个来源”，再按需要理解实现机制。对不支持写入默认模型的应用，明确“模型在目标应用中选择”，不要画一个无法兑现的全局模型选择器。

### 4.2 不用一个绿色状态概括所有结果

至少区分以下维度，而不是设计成一条简单的“草稿 → 已生效”状态链：

| 维度 | 示例 | 解释 |
|---|---|---|
| 编辑与存储 | 未保存 / 草稿已保存 | 只说明 OcHub 是否保留了编辑内容 |
| 配置写入 | 尚未写入 / 已写入版本 3 / 写入失败 | 说明目标文件或导入任务的结果 |
| 客户端读取 | 需重启 / 待应用内确认 / 无法自动确认 | 没有证据时不能声称目标工具已经采用新配置 |
| 验证 | 未验证 / 配置检查通过 / 实际请求通过 / 验证失败 | 每项写明验证对象、时间与方法 |
| 运行依赖 | 本地网关运行中 / 远程服务离线 / 直连无此依赖 | 只描述依赖，不等价于模型可用 |

例如：当前工具仍使用版本 3，用户已保存版本 4。应显示“修改已保存，尚未写入；工具配置仍为版本 3”，不能把“已保存”和“使用中”两个无解释的标签并排放置。

验证结果应绑定环境、连接配置版本或指纹、模型及验证方式。改密钥、接口地址、路由或模型后，旧成功结果保留为历史，当前状态退回“需重新验证”。若不能读到真实请求，显示“无法确认”，不把没有错误记录解释成健康。

## 5. 新信息架构

保留常用应用的直达入口。启动时恢复上次使用的应用；第一次启动和没有已配置应用时进入应用概览。

```text
OcHub
[ 本机 ▾ ]                    ← 已有工作区切换器升级；下拉中管理远程环境

应用                          ← 已发现/已配置应用的任务概览
  Codex                       ← 用户固定的应用，一次点击直达
  Claude Code
  管理应用…
模型来源                      ← 来源列表、使用范围、添加/编辑
扩展                          ← MCP / 技能
记录                          ← 会话 / 请求与用量

诊断                          ← 按环境与应用定位问题
设置                          ← 通用、应用管理、网络、数据、外观、关于
```

“应用概览”只回答哪些工具已连接、哪些需要处理，并提供添加/导入入口。不要增加与当前任务无关的连接总数、供应商总数等大号指标。

| 现有入口 | 新位置 | 迁移原则 |
|---|---|---|
| 各应用连接页 | 固定应用入口 → 连接 | 保持常用路径一步可达 |
| 模型供应商 | 模型来源 → 详情 → 接口与路由 | 普通来源信息优先；高级规则按需展开 |
| 本地网关相关运行信息 | 应用连接状态；设置 → 网络与网关 | 用户从故障现场进入，不必先找底层模块 |
| MCP / 技能 | 扩展 → MCP / 技能 | 顶部切换资源类型；保留各自发现、安装与配置能力 |
| 会话 / 用量 | 记录 → 会话 / 请求与用量 | 不把不同来源强行混成一张表 |
| 网络代理 | 设置 → 网络与网关 | 诊断结果可以直达具体设置 |
| 远程节点 | 环境切换器 → 管理环境 | 维护界面仍完整保留 |
| 高级工具 | 按功能移入诊断、应用维护、数据与备份 | 不保留无边界的杂物页 |
| 主题 | 设置 → 外观 | 保留预览和取消恢复 |
| 应用设置 | 应用页 → 设置 | 全局设置中的应用列表仅提供管理和跳转，避免重复表单 |
| 关于、更新 | 设置 → 关于与更新 | 错误或有更新时可给轻量提醒 |
| 组件画廊 | 开发入口 | 不进入普通用户导航 |

一级导航负责任务类别；页内最多保留必要的一层标签。已有全局页面和应用页是同一资源的不同筛选视角，不维护两份数据或相互矛盾的开关。

## 6. 关键页面与流程

### 6.1 应用页：当前连接就是工作中心

以下是切换型应用的结构示意，不是已实现截图。

```text
本机 / Codex                                   [启动工具 ▾]
连接    扩展    活动    设置
──────────────────────────────────────────────────────────
当前配置来源   团队 API                       [切换连接 ▾]
接入路径       Codex → OcHub 本机网关 → 团队 API
默认模型       团队编码模型     [更改]           （支持时显示）
配置状态       已写入 · 新会话或重启后读取
最近验证       10:32 实际请求通过 · 团队编码模型
                                              [验证连接] [诊断]
──────────────────────────────────────────────────────────
可用连接                                      [+ 添加连接]
名称          接入方式         配置/验证摘要          操作
官方登录      官方             已保存                 使用
备用 API      直接连接         未验证                 使用  ⋯
──────────────────────────────────────────────────────────
最近操作：10:30 写入“团队 API”                  [查看] [撤回]
```

规则：

- 页面首屏直接回答“哪台机器、哪个应用、哪条连接、是否写入、如何确认、如何恢复”。
- 当前连接区紧凑且可操作；其他连接使用便于比较的行，避免每个字段再嵌套一个卡片。
- 不支持统一“当前连接”的叠加型应用，改为“已加入此应用的连接”，逐项显示加入/移除和默认项能力。不能强行套用单选切换界面。
- 通过外部应用导入的集成，显示“已发送导入，等待应用内确认”；未收到结果前不能显示“已启用”。
- “扩展”展示当前应用可用的 MCP 与技能；“活动”链接带应用筛选的会话和请求；“设置”管理路径及该应用特有行为。
- 工具启动、官方登录、余额等仅在能力支持时显示。不支持的功能解释原因，不给一个点了才报错的按钮。

### 6.2 首次启动：先识别，再完成一个真实任务

1. 读取当前环境中可发现的工具及配置，清楚标明“扫描没有修改配置”。允许手动指定路径和跳过。
2. 对已有配置，提供“查看并导入 OcHub”；导入结果说明保存了什么，任何写回另行触发。
3. 没有配置时，选择一个目标应用并添加连接；不要求先去设置里打开应用、再找网络页。
4. 完成后回到该应用，显示写入、验证和客户端重启/确认状态。让用户从目标工具完成一次真实使用。
5. 之后再提供“用于其他应用”“添加扩展”等次要动作。

首次说明收敛为操作边界和恢复方式。备份应在实际写入前形成可靠恢复点，不把长篇首次声明当作配置保护措施。

### 6.3 添加连接：一个连续流程，可在原地添加来源

```mermaid
flowchart LR
    A[确定环境与应用] --> B[选择已有来源、官方登录或新增来源]
    B --> C[填写必要信息与兼容设置]
    C --> D[查看写入摘要]
    D --> E[保存草稿]
    D --> F[保存并写入目标应用]
    F --> G[显示结果、验证与重启说明]
    C --> H[按需展开高级设置]
    H --> D
```

界面可分成“来源 / 连接设置 / 确认”三个短步骤，不把每个字段做成一页。目标应用已从应用页确定时，不重复询问。

| 步骤 | 默认内容 | 高级内容与例外 |
|---|---|---|
| 来源 | 已有来源、官方登录、添加 API、导入已有配置 | 官方登录只提供该应用实际支持的途径；不代替用户登录 |
| 必要信息 | 名称、服务地址、密钥；按能力需要的模型 | 密钥脱敏；协议可从已知能力建议，未知时明确选择，不能猜测后强写 |
| 连接设置 | 适合目标应用的接入方式、必要模型设置 | 超时、模型映射、推理设置、额外请求头、多个接口、备用密钥、原始配置 |
| 确认 | 目标环境、应用、写入路径、连接方式、需重启说明 | 展开配置差异；外部修改冲突必须先解决 |

无来源可选时直接显示“添加模型来源”，进入内嵌子流程；返回时保留原来的目标、输入与滚动位置。不要把空状态变成去另一个页面寻找前置条件的说明书。

直连和网关的决策规则：

- 目标应用能直接使用该服务且用户不需要转换或路由时，建议直接连接。
- 需要协议转换、统一路由或故障转移时，说明具体原因并建议网关；实际支持以能力检查为准。
- 本机网关注明“需保持提供网关的服务运行”；远程网关注明“由远程服务提供，关闭本机控制界面不等于关闭远程服务”。
- 用户仍能手动选择兼容的接入方式；高级功能出现时才展开相关参数。
- 能复用已经填写的来源信息时自动回填；切换方式不静默清空另一种方式的输入。

### 6.4 保存、写入、验证：统一动词，保留能力差异

| 按钮 | 必须保证的结果 | 明确不能暗示 |
|---|---|---|
| 保存草稿 | 保留在 OcHub，目标工具配置不变 | 已切换、已联网、客户端已读取 |
| 保存并用于 Codex | 保存并执行目标应用支持的配置切换，结果可核对 | 所有工具都已经运行成功 |
| 加入 OpenCode | 写入一条支持叠加的连接 | 自动改变全局唯一“当前连接” |
| 在 Cherry Studio 中确认导入 | 触发外部导入并说明后续操作 | 导入已被接受 |
| 检查配置 | 验证格式、必填项和本地可检查约束 | 账号权限或模型可用 |
| 验证连接 | 明确执行哪类网络检查，展示分项结果 | 仅延迟成功就代表模型可用 |
| 撤回本次切换 | 对比当前配置后恢复这次操作的可恢复变更 | 覆盖之后用户或其他工具的新修改 |

这是目标契约。当前通用保存接口尚不能对所有应用承诺“保存草稿”，不能只改按钮文字就上线。过渡期间应先把现有按钮写清楚，例如“保存并更新当前配置”；通用草稿与写入分离完成后再统一到目标动作。

`⌘S` 固定保存编辑内容，不隐式切换。若底层草稿尚未支持，应先保持与可见按钮一致且明确后果，随后随契约改造一起迁移；不能让快捷键与按钮承担不同动作。

### 6.5 日常切换：短路径，可靠结果

应用页点击“切换连接” → 选择已有连接 → 后端确认结果。常规切换不重复走新增向导，也不每次弹无差别确认。

写入前生成变更计划和恢复点；发现外部修改或影响多个应用时才进入必要的影响确认。写入中禁用重复提交，保留旧状态并显示“切换中”；成功后再更新当前配置。

结果示例：

> 已将本机 Codex 的配置切换到“团队 API”。重启现有会话后读取新配置。连接尚未验证。［验证连接］［撤回］

写入失败保留原选择和输入，指出失败路径与可恢复状态。出现“来源已保存，但目标配置未写入”时分别显示结果，不用一个“保存失败”掩盖已完成部分。

撤回需要校验写入后的配置基线。遇到后续外部修改，提供差异与合并/取消选项；不声称具有跨数据库、文件和远程进程的完整事务，逐项补偿或恢复失败都必须可见。

### 6.6 未保存内容与导航

所有离开编辑的入口使用同一个决策：

- 没有修改：直接离开。
- 有修改：保留当前编辑，提供“保存草稿并离开 / 放弃修改 / 继续编辑”。如果草稿内容尚不满足持久化校验，可先提供后两项，不能伪装已保存。
- 保存或写入进行中：保留任务和结果跟踪；不因视图销毁让结果失去归属。
- 切换环境：先处理当前环境的编辑，再载入新环境；旧异步结果不能落到新环境页面。

可后续提供安全的临时草稿恢复，但需要明确存储生命周期和密钥保护；P0 不依赖自动保存密钥来解决问题。`preview_dirty` 只表示预览需要重算，不能当作用户修改过表单的标志。

## 7. 模型来源与高级路由

“模型来源”页围绕资源及使用关系组织：名称、地址摘要、可用能力、最近验证、被哪些应用连接引用。选择一项后展示详情。

| 区域 | 内容 |
|---|---|
| 基本信息 | 名称、地址、认证；凭据默认脱敏 |
| 用于哪些应用 | 应用与连接列表、使用/已加入状态、添加目标应用 |
| 接口与模型 | 按服务能力展示接口类型、模型列表与手动输入 |
| 高级路由 | 映射、故障转移、预算、多个接口、备用密钥及其他已有高级功能 |
| 验证与记录 | 检查结果、最近失败、关联请求入口 |

编辑一个被复用的来源前显示影响范围；提交前区分“仅修改这个应用的连接”和“更新来源及所选关联连接”。已引用来源的密钥修改不应静默影响所有应用。批量应用必须有逐目标计划和结果。

停用或删除被使用的来源时，列出受影响的连接，提供“先切换到其他来源”或明确的“停用并中断这些连接”。无引用资源不需要冗长确认。停用不能暗中把流量发往用户未选择的服务。

统一界面不要求立即统一数据库：首阶段保留现有按应用保存的连接与网关供应商记录，在列表中显示来源类型与作用范围。不能仅因名称或 URL 相同自动去重。后续只有明确选择复用时才建立共享引用；独立凭据、应用特例、远程环境之间仍隔离。

## 8. 扩展、记录、诊断与设置

### 8.1 MCP 与技能

资源导航共用“扩展”，页内分 MCP 和技能。MCP 的配置/分发与技能的发现/安装/更新保持各自流程。

MCP 新增支持“命令型 / HTTP 型 / 导入 JSON”。基础表单提供命令、参数、环境变量或 URL；高级用户可以直接编辑 JSON。表单与 JSON 切换不能丢失未知字段；对无法结构化的配置保留原始编辑模式。

应用分发开关继续即时执行，不再暗示还需要“提交”。在开关旁显示“正在写入 / 已写入，需重启 / 失败，重试”；失败时显示实际状态，不让开关停在没有依据的开启状态。全局同步入口改成“重新写入已启用应用”，解释其修复用途。

若未来确有批量编辑需求，再提供明确的“批量编辑”模式和待提交数量，不能在同一表面把即时开关与未提交选择混用。

技能显示来源、安装位置、版本/更新状态和目标应用。更新/卸载展示受影响目标，部分失败可以逐项重试。运行 MCP 测试或技能相关命令应是明确动作；保存配置本身不额外启动任意服务。

### 8.2 会话与请求用量

保留现有全文搜索、元数据筛选、分页/虚拟化与趋势折叠。主要改变上下文联动和信息解释：

- 从应用页进入时预置应用与环境筛选；用户可以清除筛选查看全局。返回时保留搜索条件。
- 会话展示应用、项目、时间和已有的查看/继续能力；请求展示模型、来源、耗时、结果及诊断入口。
- 网关请求与本地会话统计标明来源。聚合无法去重时分开展示，不把同一次用量加两遍。
- “无记录”“未收集”“不支持观测”“查询失败”是不同空状态；未知值不填 0。
- 费用标注估算、计价依据和覆盖情况；缺失价格显示“未计价”，不当作免费。
- 日常页面先提供近期活动与异常；价格维护移入相关设置并保留上下文直达链接。

### 8.3 诊断：围绕目标应用解释失败

入口优先来自应用状态、失败通知或请求记录；进入时携带环境、应用和连接。独立诊断页允许用户更换目标。

```text
本机 / Codex / 团队 API

配置文件             已找到、格式有效
配置一致性           与最近写入版本一致
本地网关             运行中（本连接需要）
服务连通性           通过
身份与模型权限       未检查
实际模型请求         未执行                 [发送一次验证请求]

建议下一步：验证账号是否有权限使用所选模型。
详细日志 ▾                                  [复制脱敏诊断信息]
```

诊断检查按阶段记录通过、失败、未执行、不适用；认证与模型请求可能合并在一次实际 API 请求中，不假设每个服务都有独立权限接口。服务连通检查要说明究竟测了 TCP、HTTP 还是特定接口。

实际模型验证由用户明确触发，说明可能产生少量用量，限制请求次数和输出；不为了展示进度自动对全部模型发请求。超时提供取消和重试，不把网络错误误归类成密钥错误。

错误采用“发生了什么 + 哪个目标 + 可以怎么做”：

> 无法写入远程开发机的 Codex 配置：目标目录不可写。来源已保存，应用配置未更新。［检查目录］［重试写入］

可复制诊断包默认去除密钥、认证头、敏感路径片段及会话内容；展示将包含哪些信息。完整原始日志只在明确需要时由用户选择查看。

### 8.4 设置与运行行为

| 分类 | 包含内容 | 作用范围 |
|---|---|---|
| 通用 | 语言、终端、快捷键、启动与窗口行为 | 本机控制界面 |
| 应用管理 | 发现、显示/隐藏、固定应用；跳转各应用的配置路径与维护 | 目标环境；仅显示偏好属于本机时单独标注 |
| 网络与网关 | 代理、监听地址、端口、访问控制、运行信息 | 明确选择的环境 |
| 数据与备份 | 快照、恢复、索引、同步、保留策略 | 每项展示数据位置和目标范围 |
| 外观 | 主题及现有预览功能 | 本机控制界面 |
| 关于与更新 | 版本、组件和维护入口 | 分清本机界面与远程服务版本 |

“开机启动”“关闭窗口后继续提供网关”“显示托盘图标”等设置需要给出最终行为预览。不能允许用户以为退出了服务，实际仍在运行；反之，正在使用本机网关时退出进程应清楚说明影响。

已即时保存的普通偏好继续即时保存，并给予轻量结果反馈。会更改连接、路径或运行服务的设置明确使用应用动作。设置搜索应能找到目标项及其所属页面；依赖选项折叠时也能定位并解释前置条件。

## 9. 远程环境的完整边界

现有环境选择器及远程后端保留，改进的是可见性和反馈：

1. 侧栏显示环境名与在线状态；页面标题、写入预览和结果携带环境名。重要路径标明属于远程机器。
2. 更换环境时保持有意义的任务位置；目标不支持该应用或能力时解释原因，不能回落到本机执行同一个写操作。
3. 远程断线后保留用户输入。请求超时但结果未知时，先重新读取服务端状态或查询操作结果，再决定是否重试。
4. 本机语言、主题、窗口及托盘设置明确标为“此电脑”，不随远程环境伪装成远程设置。
5. 服务升级、安装和主机身份确认保留现有必要流程；不因导航简化而自动安装软件、复制密钥或建立数据转发。
6. 关闭桌面窗口、退出本机程序、停止本机网关、停止远程服务是不同动作，文案及影响说明分别处理。

## 10. 视觉、文案与无障碍约束

本部分是设计规范和待实测验收项，不是已观测到的像素缺陷。

- 延续现有原生桌面风格与主题系统，优先改信息密度、层级和动作位置。无需先做品牌换肤。
- 页面只突出当前任务的主动作。编辑页固定底部操作区，长表单滚动时仍可保存；网关与普通连接使用相同编辑骨架。
- 高级区统一入口并记住用户展开偏好。原始配置、差异预览按需查看；窄窗口用页内切换，避免强挤并列面板。
- 名称、状态和动作不依赖悬停才出现；截断内容可以键盘访问并查看完整值。长地址不撑破布局。
- “直接连接 / 通过网关”表达类型，使用中性色；成功/失败色只表达有依据的结果，并配文字与图标。
- 空状态给出就地可完成的下一步；加载、没有结果、无权限、离线和错误分别呈现。
- 字体层级、对比度、点击目标、滚动和焦点以真实截图、AX 与键盘操作验收，不凭代码中的尺寸推断已合格。
- 目标尺寸包括 900×650 与 1280×800；在更小窗口保持纵向滚动、主动作可见。大量连接、长名称、多语言和系统缩放也要覆盖。
- 键盘可完成选择连接、编辑、保存和退出；弹层正确管理焦点并在关闭后返回触发点。开关和图标按钮的 AX 名称包含对象与目标应用。
- `Esc` 优先关闭最内层临时弹层，再进入编辑取消流程；不会直接吞掉未保存表单。

建议统一术语：

| 避免含糊表达 | 使用的表达 |
|---|---|
| 保存（实际改写当前文件） | 保存并更新当前配置，或完成语义分离后的保存草稿 |
| 已生效（只知道文件写入） | 已写入配置，重启后读取 / 等待应用内确认 |
| 测试通过（只做格式校验） | 配置检查通过，账号与服务未验证 |
| 同步（MCP 即时开关后） | 重新写入已启用应用 |
| 已连接（没有运行证据） | 已配置 / 最近验证通过，并附时间 |
| 本地服务（远程上下文中） | 此环境的网关 / 远程开发机上的网关 |
| 失败 | 具体失败对象、已完成部分、可执行的下一步 |

## 11. 工程实现边界

### 11.1 先统一行为契约

现有 `WorkspaceBackend`、应用能力查询和 provider 切换计划是可复用基础。不要在每个视图继续增加 `app == Codex` 式的例外来模拟统一体验。

建议显式表达：应用的配置模式（切换 / 叠加 / 外部导入）、能否保存草稿、写入动作、能否选择默认模型、验证方式、是否需要网关以及结果能否自动确认。UI 根据这些能力选择动词和状态。

写操作返回结构化结果：目标环境和应用、已保存部分、已写入部分、失败阶段、需要重启或外部确认的事项、可恢复操作。不能由一个 `Ok` 或通用 toast 推断所有阶段成功。

### 11.2 状态与异步任务

连接编辑状态、目标文件状态、运行依赖和验证结果分开管理。保存草稿不覆盖已应用版本；应用后记录可核对的版本/指纹；后台任务携带环境、对象与请求身份，防止切换页面后旧结果污染新页面。

按目标资源控制重复提交，保留批量操作的逐项结果。重新打开页面能看到未完成或结果未知的操作；远程重试优先支持幂等操作标识或先读后核对，不把所有失败都处理成重复写入。

### 11.3 迁移与组件归属

- 第一阶段不变更用户数据标识、不自动合并来源、不改变默认接入方式；先用现有数据构建统一视图。
- 草稿接口扩展需要同步本地、远程协议和能力协商。旧远程节点未支持时明确限制，不把普通更新当作草稿降级执行。
- 后续共享来源采用可预览的显式迁移，保留应用专属配置、未知字段与恢复记录。名称或地址一致不等于同一个账号。
- 页面组合、任务流程和业务状态属于 OcHub。通用表单、列表、焦点与编辑容器若需改动，进入独立 `ochub-ui`，主仓库不复制组件库实现。
- 用户操作和功能落地后，在相邻 `../ochub-docs` 更新文档、验证并提交。本文留在主仓库作为设计依据，不在此重建用户文档站。

## 12. 实施顺序与交付闸门

| 阶段 | 改造内容 | 用户得到的改善 | 进入下一阶段的条件 |
|---|---|---|---|
| A：先让操作可信，P0 | 修复错误连接类型；未保存离开保护；现有保存按钮如实标注；停用影响提示；明确部分成功；修正 MCP 实际行为对应的用户说明 | 不再靠猜测点击，不轻易丢输入，不把配置写入当成运行成功 | 保存/写入行为矩阵和关键回归用例通过 |
| B：打通核心任务，P1 | 通用草稿与应用契约；重做应用连接页；原地添加来源；首次接入与切换；验证与撤回 | 在一个连续上下文完成接入、切换和恢复 | 首次接入、既有连接切换、外部冲突、远程路径验收通过 |
| C：重组完整应用，P1/P2 | 新导航；模型来源统一视图；扩展、记录、诊断、设置归位；全局与应用上下文联动 | 用户按任务找功能，出错有明确排查路径 | 原有功能入口映射完成，无功能丢失；所有环境能力正确 |
| D：验证并优化 | 可用性测试、键盘与 AX、尺寸/多语言、长列表；修正观察到的阻碍 | 流程在真实任务和数据规模下稳定 | 下节验收项通过并记录剩余限制 |

共享来源数据库迁移是后续可选项目，不应成为 A/B 阶段的前置大工程。来源统一视图先通过关联信息和明确的“用于其他应用”动作提供价值。

建议首个实现批次严格限定为：未保存保护、状态标签修复、保存后果如实表达、停用影响提示。随后把“首次配置一个应用 → 切换到另一连接 → 失败后恢复”作为贯穿改造的样板流程。

现阶段不承诺精确排期。通用草稿、历史配置恢复和旧远程协议兼容是需要先评估的工程成本；确定能力矩阵和接口改动后再估算各批次，避免把这次工作误估为单纯页面重排。

## 13. 验收与验证计划

### 13.1 用户任务验收

下列时间与步骤是目标，不是本次测得的结果。准备好有效服务信息、网络正常时进行；外部登录等待、服务响应和用户自行重启的耗时单独记录。

| 场景 | 验收结果 |
|---|---|
| 第一次使用，已有工具配置 | 能导入或跳过；扫描与只读预览不修改目标文件；用户说清当前是否受 OcHub 管理 |
| 第一次使用，已有有效 API 信息 | 5 分钟内完成一个应用的配置写入并找到验证入口；无需离开接入流程寻找供应商管理 |
| 日常切换已保存连接 | 从应用页通常两次选择完成；例外只在冲突或重大影响时增加步骤；能找到撤回 |
| 编辑到一半切换页面、应用或环境 | 不静默丢失内容；保存失败留在原上下文且输入完整 |
| 保存已应用连接的新草稿 | 原目标文件不变；UI 同时显示旧应用版本与新草稿 |
| 同一来源用于两个应用 | 兼容差异可见；一个失败不把另一个标成失败或把整体标成成功 |
| 停用被使用的来源 | 用户先看到受影响目标；没有隐式切到其他服务 |
| MCP 开关写入失败 | 明确目标与原因；开关状态有依据；重试不要求重新输入配置 |
| 密钥错误或模型无权限 | 区分已知与推断，保留输入，提供具体下一步；格式正确不会显示可用 |
| 外部工具修改过配置 | 应用或撤回前显示冲突；未知字段及无关配置不会被静默覆盖 |
| 远程执行时断线 | 不误更新本机；重连后核对目标结果，避免盲目重复执行 |
| 外部应用接收导入 | 发送成功与导入确认分开；不能在不可观测时显示最终启用成功 |
| 直连应用无请求记录 | 显示覆盖限制，不用零用量或健康状态代替未知 |
| 本机网关使用中退出 | 说明受影响连接及退出行为；远程服务的生命周期单独解释 |
| 窄窗口、长名称、键盘操作 | 主动作可见，焦点清楚，内容可访问，AX 名称能区分对象与操作 |

可用性验证建议分两轮，每轮覆盖首次接入、多工具管理和远程/高级情境。第一轮用流程原型找任务阻碍，第二轮在实现后的固定 QA 包中复验。记录完成率、误操作、求助次数及用户对当前状态的解释；小样本用于发现问题，不把它包装成统计结论。

### 13.2 工程验收

- 先建立所有受支持应用的能力/行为矩阵，覆盖切换、叠加、外部导入、官方登录、草稿、默认模型与远程能力；不能只测 Codex。
- 核心测试聚焦实际配置副作用、外部冲突、部分失败、恢复、任务作用域及协议兼容。纯布局调整不添加只复述组件树的测试。
- 每个实现批次运行相关测试和仓库要求的格式/静态检查；通过后不因无关改造重复扩大范围。
- GPUI 修改后使用 `just qa-app` 构建固定 `/tmp/OCHUB-QA.app`，复用 Bundle ID `io.ochub.debug.qa`。
- 用 computer-use 的 node_repl/sky 按固定路径启动，读取 AX 树、按索引操作、操作后刷新状态并截图；验收任务结果、布局和文案。
- 验收后退出应用，保留固定 QA 包供下次覆盖；不生成随机包路径或 Bundle ID。
- 涉及实际用户操作变化时，更新独立用户文档仓库，运行其验证并提交对应文档；文档描述以已实现行为为准。
