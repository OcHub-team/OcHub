Every version tag is built on the matching native GitHub-hosted runner.

## Homebrew (macOS)

Homebrew automatically selects the Apple Silicon or Intel build:

```sh
brew install --cask ochub-team/tap/ochub
```

Upgrade or uninstall OcHub with:

```sh
brew upgrade --cask ochub-team/tap/ochub
brew uninstall --cask ochub
```

The Cask is maintained in the
[`OcHub-team/homebrew-tap`](https://github.com/OcHub-team/homebrew-tap)
repository and downloads the same DMG published with each GitHub Release.

## Direct downloads

| Platform | Release files |
| --- | --- |
| macOS Apple Silicon | ARM64 `.dmg` |
| macOS Intel | x64 `.dmg` |
| Windows 10/11 x64 | NSIS installer and portable `.zip` |
| Linux x64 | AppImage and Debian `.deb` |

The release also includes `SHA256SUMS` and a GitHub artifact attestation. Verify
a downloaded file with:

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <downloaded-file> --repo OcHub-team/OcHub
```

## macOS: approving the app on first launch

OcHub is signed with a self-signed certificate and is not notarized by Apple.
Gatekeeper trusts only certificates that chain back to Apple's own root, and a
self-signed one does not, so macOS asks you to approve OcHub once. This is
expected for OcHub and does not mean the download is broken.

### Approve it in System Settings

<Steps>

1. Open OcHub. macOS says it cannot verify the developer.

2. Go to **System Settings › Privacy & Security**, scroll to Security, and
   click **Open Anyway**.

</Steps>

Control-clicking the app no longer works for this on macOS 15 and later — the
System Settings route is the only one.

### Or clear the quarantine flag in Terminal

Use this when **Open Anyway** never appears, when macOS calls OcHub *damaged*,
or when you would rather not deal with the prompt at all.

macOS attaches a `com.apple.quarantine` attribute to everything a browser
downloads, and Gatekeeper only inspects apps carrying it. Removing that
attribute lets OcHub open normally.

<Steps>

1. Open the downloaded `.dmg` and drag **OcHub** into your **Applications**
   folder. The command below expects it there.

2. Open Terminal: press <kbd>⌘</kbd> <kbd>Space</kbd>, type `Terminal`, and
   press <kbd>Return</kbd>.

3. Paste this line exactly as written and press <kbd>Return</kbd>:

   ```sh
   sudo xattr -rd com.apple.quarantine /Applications/OcHub.app
   ```

4. Type your Mac login password and press <kbd>Return</kbd>. Nothing appears
   on screen while you type the password — that is how Terminal always behaves,
   not a stuck prompt.

5. Open OcHub. It launches without any warning.

</Steps>

`sudo` is needed because the attribute lives on the installed app rather than
on your own copy of it, and `-r` applies the change to everything inside the
bundle. No output means it worked.

<Aside type="caution" title="Only run this on an app you downloaded yourself">

Clearing the quarantine flag switches off a real macOS safety check for that
app. Run it only for OcHub, only with the exact path above, and only when you
downloaded the DMG from OcHub's own release page. Never paste an `xattr`
command someone else hands you for software you did not go and fetch yourself.

</Aside>

If you installed with Homebrew, you can skip the flag at install time instead:

```sh
brew install --cask --no-quarantine ochub-team/tap/ochub
```

Updates installed from inside OcHub are never quarantined, so either route is a
one-time step rather than something you repeat on every release.

Windows SmartScreen may warn for the same reason.

## Updating

OcHub checks for a new release shortly after launch and once a day after that,
and can install one from **Settings → About → Check for updates** without
leaving the app. Turn the check off with the toggle in the same group.

Downloaded packages are verified against a signing key compiled into the
binary, and a version that is not newer than the running one is refused, so the
update channel cannot be used to push unsigned code or to roll an install
backwards.

Two install methods stay check-only, because self-updating them would fight the
system that owns them:

| Install | In-app update |
| --- | --- |
| macOS `.dmg`, Windows installer, Linux AppImage | Yes |
| Debian package | No — use `apt`, so dpkg's records stay accurate |
| Windows portable ZIP | No — there is no installer to re-run |

Those two report the reason in the settings row and link to the release page.
