高度な機能はルーティング、履歴、ツール設定へ直接影響します。先に通常の接続を 1 つ完成
させ、実際のリクエストが成功する既知の状態を用意してください。

## 推奨する順序

| 目的 | ガイド |
| --- | --- |
| エイリアス、プロトコル変換、例外で実際のルーティングを構成 | [ルーティング実践](/ja/advanced/routing-recipes) |
| トークンコストを価格、倍率、請求の基準へ合わせる | [モデル価格とコスト調整](/ja/advanced/pricing) |
| スナップショットを WebDAV または S3/R2 で同期 | [データ、バックアップ、同期](/ja/advanced/data-sync) |

## 自動ルーティングとプロトコル変換

1 つのモデルプロバイダーで次を有効にできます。

- Anthropic Messages
- OpenAI Chat
- OpenAI Responses

自動ルーティングはクライアントのネイティブインターフェースを優先し、そこでモデルが
使えないか障害がある場合に、変換可能な別のインターフェースを試します。少なくとも 1 つを
有効にし、上流資料に明確な制限がある場合は手動で設定します。

## デフォルトモデル

デフォルトモデルを設定すると、モデル例外に一致しないリクエストでそのモデルを使います。
1 モデルだけを公開する上流に適しています。

「念のため」設定すると、クライアントのモデル名の誤りが隠れたり、異なる用途が同じモデルへ
集約されたりします。

## モデル例外

自動ルーティングで表現できない場合だけ追加します。

| フィールド | 用途 |
| --- | --- |
| モデルまたはパターン | クライアントモデルをワイルドカード込みで照合 |
| インターフェース | 有効な 1 つへ固定、または自動選択 |
| 上流モデル | クライアントモデルを変更。空なら維持 |

具体的なルールを広いパターンより前に置き、実リクエストで確認します。参照する
インターフェースは有効のままにしてください。

優先順位と例は[ルーティング実践](/ja/advanced/routing-recipes)にあります。

## 推論の強度

- **自動マッピング**：CLI の強度レベルと上流のトークン予算を変換。
- **そのまま渡す**：クライアントの推論パラメーターを変更しない。
- **推論を無効化**：関連パラメーターを削除または無効化。

自動マッピングの低、中、高、最大は、すべて正の昇順値にします。上流が予算ではなく強度名
だけを受け付ける場合は、その API 仕様を優先します。

## 高速切り替えと予備上流

一度モデルプロバイダーを適用すると、ツール設定を書き直さずアプリページから上流を切り替えられます。

予備を検証しておき、主系障害時は：

1. アプリを予備のモデルプロバイダーへ切り替えます。
2. 短いリクエストを送ります。
3. 使用量で状態とレイテンシーを比較します。
4. 復旧後に戻し、障害中はモデルルールを同時変更しません。

自動ルーティングが選択・再試行するのは 1 つのモデルプロバイダー内のインターフェースです。主系と
予備のカード間は手動切り替えです。

## 使用量と価格

リクエストが成功してコストが 0 の場合、課金モデルに価格がない可能性があります。詳細画面の
リクエストモデル、モデル、課金モデルを記録し、入力、出力、キャッシュ読み書き価格を設定します。

Claude と Codex にはデフォルト倍率と課金モデル元もあります。エイリアスやルーティング
変更後は、課金モデルが実際の請求対象を表すか確認します。詳細は
[モデル価格とコスト調整](/ja/advanced/pricing)を参照してください。

## 接続の高度な編集

### 共通設定

共通設定はアプリ単位の共有スニペットです。**この接続へ共通設定を適用**を有効に
すると、書き込み時にマージされます。

現在の設定から抽出する前に、特定の接続だけのキーやモデルが含まれていないことを
確認します。

### 生ファイル編集

「書き込むファイル」の編集から生成内容を直接変更できます。適用後、OcHub は変更をフォームへ
反映しようとします。

フォームで表現できない対応フィールドだけに使い、保存前にプレビューを更新してカスタム項目が
残ることを確認してください。

## CLI ツールのメンテナンス

**高度なツール**を開きます。

1. **バージョンを更新**でローカル、最新、環境元を確認。
2. **インストール先をスキャン**で `PATH` の既定、重複、壊れた実行ファイルを確認。
3. 不足時は**不足ツールをインストール**。
4. **すべて更新**は表示されたコマンドを実行。内容と確認要否を先に確認。

複数のパッケージマネージャーが同じ CLI を入れている場合は、残すものを決めて `PATH` を
手動整理します。OcHub は未知のインストールを削除しません。

## 環境変数の競合

設定ファイルを上書きし得る環境変数をアプリ別に検出します。**削除してバックアップ**の前に：

1. 変数名と対象アプリを確認。
2. バックアップパスを記録。
3. 変更後にターミナルと CLI を再起動。
4. 元に戻す場合は**バックアップを復元**でパスを指定。

変数が再び現れる場合は、シェル設定、ランチャー、管理ポリシーなど実際の提供元を調べます。

## アプリ固有の高度なツール

| ツール | 機能 |
| --- | --- |
| Codex | 統合履歴バックアップの確認、公式履歴の復元 |
| Claude | オンボーディングのスキップ／復元、OcHub プラグイン、MCP の読み取りと検証 |
| OpenCode | OMO / OMO Slim の読み取りと無効化 |
| OpenClaw | 設定チェック、デフォルトモデル、環境、ツール JSON |
| Hermes | モデル JSON、MEMORY、USER、各有効状態 |

ファイルを上書きする場合があります。OpenClaw、Hermes、環境変数操作では可能なとき
バックアップを作成します。表示されたパスを記録してください。

復元とリモート同期は[データ、バックアップ、同期](/ja/advanced/data-sync)、cc-switch は
[移行ガイド](/ja/guides/migration)を参照してください。
