プロバイダー、MCP、スキルリポジトリ、設定、一部の使用量は OcHub データベースに保存されます。
リモート同期はデータベースと管理スキルのスナップショットをアップロードします。各 AI
ツールの実設定ディレクトリ全体を同期するものではありません。

## ローカルデータディレクトリ

既定は `~/.ochub/` で、データベース、バックアップ、管理スキルが含まれます。
**設定 → データとバックアップ**から変更できます。

変更後は OcHub を再起動し、画面とバックグラウンドサービスが同じ場所を使うようにします。
既定へ戻しても 2 つのディレクトリは自動統合されません。

## 自動バックアップ

- **自動バックアップ間隔**：ローカルスナップショットを作る頻度。
- **保持数**：上限を超えた古いバックアップを削除。

設定変更が多い時期は短い間隔を使い、容量が限られる場合は保持数を減らします。

## 手動バックアップと復元

**高度なツール → データベースバックアップ**を開きます。

1. **バックアップを作成**します。
2. 用途と日付が分かる名前へ変更します。
3. 復元前に名前を確認します。OcHub は現在のデータベースも安全バックアップします。
4. 復元後に再起動し、プロバイダー、MCP、スキル、設定を確認します。

削除は元に戻せません。少なくとも 1 つは使用中のデータディレクトリ外へ保管してください。

## リモート保存先を選ぶ

WebDAV と S3 互換ストレージに対応します。1 つの設定では 1 つの保存先を使います。両方が
有効と検出された場合、直近の同期から現在の対象を推定するため、保存前に再確認します。

<Tabs>

<TabItem label="WebDAV">

WebDAV URL、ユーザー名、パスワードを入力します。URL は `http://` または `https://` で
始めます。

</TabItem>

<TabItem label="S3 / R2">

Access Key ID、Secret Access Key、Region、Bucket を入力します。AWS S3 はカスタム Endpoint
を空にできます。Cloudflare R2 は提供された Endpoint とリージョン `auto` を使うのが一般的です。

</TabItem>

</Tabs>

共通項目：

- **プロファイル**：同じリモート内の論理名。既定 `default`。
- **リモートディレクトリ**：スナップショットのルート。既定 `ochub-sync`。

複数端末で共有するには、保存先、ディレクトリ、プロファイルを一致させます。

## テスト、保存、アップロード

1. 接続情報を入力します。
2. **テスト**します。テストは入力内容を保存しません。
3. ページ下部の**保存**を選びます。
4. 保存後に**ローカルスナップショットをアップロード**します。
5. 最終同期時刻とエラーを確認します。

自動同期はデータベース変更後にアップロードをキューします。リアルタイムの双方向マージでは
ないため、複数端末で同時編集すると後のスナップショットが前を上書きする可能性があります。

## リモートから復元する

1. 他端末での変更を止めます。
2. 保存先、プロファイル、最終同期時刻を確認します。
3. 復元を確定します。
4. OcHub がローカルをバックアップしてから置き換えます。
5. 再起動して重要な設定を確認します。

安全バックアップ作成後に復元が失敗した場合は、繰り返す前に接続問題を解決してください。

## cc-switch から再インポートする

**設定 → データとバックアップ → cc-switch からインポート**で再実行できます。同じ ID は
cc-switch 側で置き換えられ、先にデータベーススナップショットが作られます。
`~/.cc-switch/` は読み取り専用です。

初回移行、競合、段階的な確認、ロールバックは
[cc-switch から移行](/ja/guides/migration)を参照してください。
