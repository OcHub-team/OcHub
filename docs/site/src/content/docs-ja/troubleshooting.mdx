一度に 1 つの変数だけを変更します。OcHub が正しく書かなかったのか、ツールが再読み込み
していないのか、上流が拒否したのかを先に判断します。

## 共通の確認順序

1. OcHub に表示された完全な状態メッセージを記録します。
2. 現在のアプリ、プロバイダー、ステーションを確認します。
3. 「書き込むファイル」を展開し、パスと重要項目を確認します。
4. 対象 CLI を再起動し、最短のリクエストを送ります。
5. リレー使用時は OcHub が動作中であることと使用量ログを確認します。
6. 最後にモデルマッピング、推論、環境変数を変更します。

## 保存成功後もツールが変わらない

- 保存だけでなく**切り替え**または**ツールに追加**を実行したか確認。
- アプリのカスタム設定ディレクトリを確認。
- 実行中の CLI を終了。既存プロセスが設定をキャッシュしている場合があります。
- 外部変更の競合や別の管理ツールによる書き込みを確認。
- OpenCode、OpenClaw、Hermes は複数プロバイダー共存、Claude、Claude Desktop、
  Codex、Grok Build は現在のプロバイダーを重視するため操作が異なります。

## アドレスには到達するがリクエストが失敗する

URL テストや接続チェックは任意の HTTP 応答を到達可能と判断することがあります。

- キーがそのアドレス用か。
- モデルがそのインターフェースで提供されるか。
- Anthropic、OpenAI Chat、OpenAI Responses のどれが必要か。
- 残高、割り当て、アクセス権があるか。
- デフォルトや例外でモデルが変更されていないか。
- 上流の正確な状態コードとエラー。

## リレーステーションへ接続できない

- カードが有効か確認。
- 保存だけでなくアプリへ適用済みか確認。
- 接続チェックでローカルゲートウェイと上流の問題を分離。
- 検証済み直接接続へ一時的に戻し、CLI 自体を確認。

起動時に制御 API ポート使用中と出た場合は、占有プロセスを終了して再起動するか `MS_PORT`
で別ポートを指定します。画面とリレーは動いても、制御 API 依存の連携は使えない場合があります。

## MCP がアプリに表示されない

- サーバーカードで対象アプリが有効か。
- トグル変更後に**アプリへ同期**したか。
- JSON がオブジェクトで、正しい `type`、`command`、`url` を持つか。
- stdio コマンドが対象ツールから見える `PATH` にあるか。
- 対象アプリと設定ディレクトリが正しいか。
- 同期後にアプリを再起動したか。

## スキルのインストール／更新に失敗する

- ネットワークとリポジトリ URL を確認。
- `owner/repo`、`owner/repo@branch`、GitHub URL を使用。
- skills CLI が利用可能か確認。
- ディレクトリ競合時は既存内容を確認し、すぐに上書きしない。
- 一括更新の一部失敗は個別に処理。

## セッションまたは使用量が空

- 対応 CLI が実際に書いた履歴だけを読み取ります。
- 設定ディレクトリ、期間、アプリフィルターを確認。
- 更新してスキャン完了を待ちます。
- 使用量のプロバイダー、モデル、状態フィルターをリセット。
- ゲートウェイのレイテンシーを安定して持つのはリレーリクエストだけです。

## 同期または復元に失敗する

- 保存済み WebDAV / S3 を再テスト。
- Endpoint、Region、Bucket、リモートディレクトリ、プロファイルを確認。
- テスト成功後も**保存**が必要。
- ローカル安全バックアップを作れない場合、復元は中止されます。
- 複数端末から異なるスナップショットを同時アップロードしない。

## 解決しない場合

報告に次を含めます。

- OcHub バージョン、OS、インストール方法。
- 対象アプリと接続方法。
- 最短の再現手順。
- 完全なエラーテキスト。
- キー、トークン、個人セッションを除いた設定プレビュー。
