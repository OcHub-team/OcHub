## アカウントとモデルの接続先

モデルの接続先として**公式**、**モデルプロバイダー**、**手動設定**を選び、アカウントには **ChatGPT** または**使用しない**を指定します。ログインは Codex で行います。ChatGPT を選択するだけではログインや契約の検証は完了しません。

1. モデルプロバイダーに URL、API キー、プロトコル、モデルを登録します。
2. Codex 接続を追加し、そのプロバイダーを選びます。実ログインを保持する場合は ChatGPT を選びます。
3. モデルを選択し、コンテキスト管理は**自動**のままにします。
4. 設定を確認して保存・切り替えを行い、Codex の新しいセッションを開始します。

第三者の API キーはプロバイダー側で管理します。手動設定の場合のみ接続に URL とキーを入力します。独立した API キーと実ログインの併用だけでは、実験的コンテキスト管理の条件を満たしません。

**保存**は Codex 接続の下書きのみを保存し、現在の接続ファイルを書き換えません。**保存して有効化**は保存後に切り替え、外部の設定変更を保持します。**設定を確認**はローカル条件のみを確認し、推論要求、契約やサービスの検証は行いません。リモート環境には下書き操作に対応する更新済みノードが必要です。

仮想ログインは**詳細設定**にあります。実アカウントを持たないクライアントの互換性用であり、公式の契約や利用枠は付与しません。実ログインを上書きすることもできません。

## コンテキスト管理

| 選択 | 動作 |
| --- | --- |
| 自動 | 公式の既定エンドポイントでは Codex の実験機能を設定。第三者や OcHub のルートでは自動的に有効化しません |
| 有効 | 実験機能を要求。履歴サービスのない OcHub ルートでは保存を拒否します |
| 無効 | エンドポイントを再設定しても実験機能を有効化しません |

検証待ちの表示は設定状態であり、契約やサービスの利用可能性を保証しません。履歴サービス未接続の表示は、OcHub に必要なサービスが実装されていないことを示します。

実 ChatGPT ログイン、第三者の推論、完全な実験的コンテキスト管理の組み合わせは、現在、動作が確認された対応機能ではありません。0.5.16 の文書ではログインの関連付けと圧縮転送を完全な対応と誤って説明していました。ここで訂正します。

### 自動有効化の条件

対応する Codex ソースの `apply_experimental_context` は次の条件をすべて確認します。

- `[features.context_management] experimental_mode = true`。
- Provider 名が正確に `OpenAI`。
- URL が未設定、または末尾のスラッシュを除いて `/backend-api/codex` で終わる。
- `requires_openai_auth = true`。
- `env_key`、`experimental_bearer_token`、`auth`、`aws` が存在しない。空文字も存在として扱われます。
- 認証が `Chatgpt`、契約が Plus、Pro、ProLite のいずれか。
- Token Budget を有効化でき、管理ポリシーで無効に固定されていない。

通過すると Token Budget と `use_history_notes_extension` が設定されます。実際の利用には、モデルのコンテキスト長、History / Notes 拡張、履歴取り込み・検索・ノートのサービスも必要です。Token Budget の明示設定やモデル既定値は別の有効化経路です。

### 履歴と圧縮

履歴機能には `alpha/history/v2/*` と `alpha/notes/v2/*` が必要です。`thread_hint`、履歴検索、ノートの読み書きを含みます。OcHub はこれらのサービスや、第三者推論の履歴を公式サービスに取り込む経路を実装・検証していません。

`/responses/compact` はリモート圧縮のみです。OcHub は `/v1/responses/compact` と Codex バックエンド形式の圧縮要求を、対応する Responses 上流へ転送します。Chat / Messages への変換では代替できません。

## モデル機能の宣言

**モデルプロバイダー → 編集 → モデル**で、選択したモデルの**モデル機能**を開きます。

| 項目 | 意味 |
| --- | --- |
| Responses Lite：自動 | 未宣言として無効。同名の公式モデルから推測しません |
| Responses Lite：対応 / 非対応 | 生成する Codex カタログの `use_responses_lite` を明示設定 |
| リモート圧縮：自動 | 未検証。実際の Responses 要求で利用可能性を確認 |
| リモート圧縮：対応 | ユーザーの宣言。実要求による検証が必要 |
| リモート圧縮：非対応 | このモデルの圧縮要求を拒否 |
| コンテキスト長 | 正の整数。空欄はカタログ既定値 |

**ユーザー指定 · 未検証**と表示します。モデル一覧の取得だけでは Lite、圧縮、履歴機能を検証できません。宣言はプロバイダーと上流モデルごとに保存し、別名には対応する上流モデルの宣言を適用します。

Lite は Responses の要求動作であり、認証方式でもコンテキスト管理の前提条件でもありません。Lite 要求はネイティブ Responses のみを使用し、Chat / Messages に変換しません。

## ルートの分離

実ログイン用に生成する URL は次の形式です。

```text
http://127.0.0.1:4180/connection/rd-…/backend-api/codex
```

URL 内のローカルキーがプロバイダーを指定します。アカウント認証は `auth.json` に保持し、OcHub は上流にプロバイダーの API キーを使用します。ローカルのルート認証情報は上流へ転送しません。異なるプロバイダーが単一の OAuth 関連付けを共有することはありません。

URL はローカル認証情報を含むため公開しないでください。待受はループバックのみです。ルート認証は ChatGPT 契約を検証しません。キーを無効化すると接続を拒否します。

`/connection/…` を含まない旧 URL は、手動のグローバル OAuth 関連付けを引き続き使用できます。接続を再保存・有効化して移行してください。

## ローカル履歴、MCP、スキル

履歴の統一・移行はローカルのセッションファイルを扱い、実験的 History / Notes バックエンドとは別です。履歴の保存場所を変える前に Codex を終了し、バックアップを保持してください。MCP とスキルは各ページで Codex を有効化して同期します。

[Codex の詳細設定](/ja/codex/advanced)と[モデルプロバイダー](/ja/getting-started/relay)も参照してください。
