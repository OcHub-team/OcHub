Claude Code と Claude Desktop はどちらも「現在の接続を切り替える」方式です。
実設定は 1 つの現在接続を指します。同じ Claude エコシステムでも、OcHub が管理できる
機能は異なります。

| 機能 | Claude Code | Claude Desktop |
| --- | --- | --- |
| 直接接続と公式ログイン | 対応 | 対応 |
| モデルプロバイダー | 対応 | 対応 |
| MCP 管理 | 対応 | 非対応 |
| スキル配布 | 対応 | 非対応 |
| Claude プラグイン連携 | 対応 | 対象外 |
| セッション読み取り | 対応 | 主なセッション元ではない |

ターミナル中心なら Claude Code を先に設定します。デスクトップクライアントでサードパーティー
接続が必要な場合だけ Claude Desktop を別に設定します。接続は自動共有されません。

## Claude Code の直接接続

<Steps>

1. **Claude Code を開きます。** アプリ一覧から選び、**接続を追加**します。

2. **エンドポイントを入力します。** プロバイダーの Anthropic 互換 Base URL を使います。
   Claude Code はその後に `/v1/messages` を要求するため、通常の Base URL に完全な
   Messages パスを重ねないでください。

3. **認証変数を選びます。** サードパーティーのサービスは通常
   `ANTHROPIC_AUTH_TOKEN`（Bearer）、Anthropic 公式キーは通常
   `ANTHROPIC_API_KEY`（x-api-key）です。上流の要求するヘッダーを優先します。

4. **API キーを入力します。** OcHub は選んだ変数だけへ書き込み、互いに排他的なもう一方を
   削除します。

5. **最初は 1 モデルだけ設定します。** デフォルトモデルは個別設定のない役割の
   フォールバックです。

6. **プレビューを確認します。** 「書き込むファイル」を展開し、対象の `settings.json` と、
   hooks、permissions、statusline など既存項目が保持されることを確認します。

7. **保存して切り替えます。** 保存は OcHub へ追加、切り替えは現在の Claude Code 接続へ
   反映します。

8. **新しいターミナルで確認します。** 既存セッションを終了し、短いリクエストを送り、
   使用量またはプロバイダー側ログを確認します。

</Steps>

まず認証変数を確認してください。

## 役割モデルを設定する

OcHub は Claude Code の各役割を `ANTHROPIC_DEFAULT_*_MODEL` へ書き込みます。

| 役割 | 一般的な用途 | 空の場合 |
| --- | --- | --- |
| sonnet | 日常のコーディングと汎用作業 | デフォルトモデル |
| opus | 高度な推論 | デフォルトモデル |
| haiku | 高速で低コストな作業 | デフォルトモデル |
| fable | 対応環境の追加役割 | デフォルトモデル |

各行にモデル ID、表示名、1M コンテキストを設定できます。1M を有効にすると ID に `[1M]`
が付き、haiku では利用できません。上流が対象モデルとコンテキストを明示的に対応する場合だけ
有効にします。

安全な手順：

1. デフォルトモデルを実リクエストで確認。
2. sonnet に同じ検証済みモデルを追加。
3. opus、haiku、fable を 1 つずつ追加。
4. 毎回テストし、モデルと認証の問題を同時に起こさない。

## 公式ログインを使う

Claude Code ですでにログイン済みなら、公式ログインの接続を追加します。
サードパーティー URL やキーを書かず、Claude Code 自身のアカウント状態を利用します。

- サブスクリプションとサードパーティー API を切り替える。
- アドレス、キー、割り当ての問題を切り分ける。
- ネイティブのアカウント機能を維持する。

切り替え後も旧アドレスを使う場合は、CLI を再起動し、
**高度なツール → 環境変数の競合**で `settings.json` を上書きする値を探します。

## MCP、スキル、プラグイン

### MCP

1. MCP サーバーで Claude の既存設定をインポートするか、新規追加します。
2. カードの Claude Code を有効にします。
3. **アプリへ同期**します。
4. Claude Code を再起動して確認します。

MCP は通常 Claude 設定ディレクトリの隣にある `~/.claude.json` へ推定されます。カスタム
ディレクトリ使用時は同期前に実際のパスを確認してください。

### スキル

インストール時に Claude Code を選ぶか、インストール済みカードで有効にします。skills CLI
に依存するため、失敗時は**高度なツール → CLI ツールのメンテナンス**でバージョンと
`PATH` を確認します。

### Claude プラグイン連携

アプリ設定の「Claude プラグイン連携」はスキルと MCP にプラグイン関連設定への書き込みを
許可します。完全に手動管理する場合だけ無効にしてください。

「Claude オンボーディングをスキップ」は MCP 導入済みとして扱います。公式フローへ戻すには
高度なツールの「Claude オンボーディングを復元」を使います。

## Claude Desktop を設定する

1. Claude Desktop のアプリページを開きます。
2. Base URL とキーを持つサードパーティー接続、または公式ログインを追加します。
3. プレビューで Claude Desktop の保存先を確認します。
4. 保存して切り替えます。
5. Claude Desktop を完全終了して開き直し、短いリクエストを送ります。

OcHub は Claude Desktop の MCP とスキルを管理しません。拡張はクライアント自身の設定を
使用してください。

## カスタム設定ディレクトリ

Claude Code の既定は `~/.claude` です。仕事用と個人用、マウントされた保存先、テスト用を
分ける場合にアプリ設定から変更できます。

保存後に OcHub と Claude Code を再起動し、パスを再確認します。設定、MCP、セッションの
読み取り先が変わりますが、旧ディレクトリの内容は自動移動しません。

## よくある問題

| 症状 | 最初に確認 | 対処 |
| --- | --- | --- |
| 401 | 認証変数とキー | Bearer と x-api-key の要件を合わせる |
| 404 | Base URL に完全な `/v1/messages` がある | 上流の基点へ戻す |
| モデルがない | デフォルト／役割マッピング | 上流の実 ID を使用 |
| 旧アドレスを使う | 既存ターミナル、環境変数 | 再起動して競合をスキャン |
| MCP がない | Claude トグル、ディレクトリ、JSON | 再同期して再起動 |
| 既存設定消失の危険 | プレビュー、ドリフト警告 | キャンセル、バックアップ、比較 |

コピーや設定ドリフトは[接続を管理する](/ja/guides/providers)、共有機能は
[MCP とスキル](/ja/guides/mcp-skills)を参照してください。設定優先順位、ゲートウェイ互換性、
指示の読み込み、MCP スコープは
[Claude Code の高度な設定と落とし穴](/ja/claude/advanced)を参照してください。
