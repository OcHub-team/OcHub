すべてのバージョンタグは、対応するネイティブの GitHub ホストランナー上でビルドされます。

## Homebrew（macOS）

Homebrew が Apple Silicon 版と Intel 版を自動的に選択します：

```sh
brew install --cask ochub-team/tap/ochub
```

アップグレードとアンインストール：

```sh
brew upgrade --cask ochub-team/tap/ochub
brew uninstall --cask ochub
```

Cask は
[`OcHub-team/homebrew-tap`](https://github.com/OcHub-team/homebrew-tap)
リポジトリで管理されており、各 GitHub Release で公開されるものと同じ DMG を
ダウンロードします。

## 直接ダウンロード

| プラットフォーム | 配布ファイル |
| --- | --- |
| macOS Apple Silicon | ARM64 `.dmg` |
| macOS Intel | x64 `.dmg` |
| Windows 10/11 x64 | NSIS インストーラーとポータブル `.zip` |
| Linux x64 | AppImage と Debian `.deb` |

リリースには `SHA256SUMS` と GitHub の成果物アテステーションも含まれます。
ダウンロードしたファイルの検証：

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <downloaded-file> --repo OcHub-team/OcHub
```

## リモートノード用 headless CLI

各リリースには macOS、Windows、Linux 用の headless archive もあります。
次の 2 つが含まれます。

- `ochcli`：command-line control surface と Remote Nodes protocol server。
- `ochubd`：`ochcli` が利用する persistent Runtime Owner。

同じリリースの両方を同じディレクトリへ置きます。Linux または WSL の例：

```sh
tar -xzf OcHub_*_linux_x86_64_cli.tar.gz
sudo install -m 0755 ochcli ochubd /usr/local/bin/
ochcli version
ochcli remote probe
```

Desktop は接続時に system OpenSSH 経由で
`ochcli remote serve --stdio` を起動します。この protocol を network listener
として公開しないでください。SSH、WSL、host key、Provider import、切り替え手順は
[SSH でリモートノードを操作する](/ja/guides/remote-nodes)を参照してください。

## macOS：初回起動時の承認

OcHub は自己署名証明書で署名されており、Apple の公証は受けていません。
Gatekeeper が信頼するのは Apple のルート証明書までたどれる証明書だけで、
自己署名証明書はたどれないため、macOS が一度だけ承認を求めます。これは OcHub では
正常な動作であり、ダウンロードが壊れているわけではありません。

### 方法 1：システム設定で承認する

<Steps>

1. OcHub を開きます。macOS が開発元を検証できないと表示します。

2. **システム設定 › プライバシーとセキュリティ**を開き、「セキュリティ」まで
   スクロールして**このまま開く**をクリックします。

</Steps>

macOS 15 以降では、アプリを Control クリックする従来の方法は使えません。
システム設定から行う方法だけが有効です。

### 方法 2：ターミナルで検疫フラグを外す

**このまま開く**が表示されない場合、macOS が OcHub を「損傷している」と表示する
場合、あるいは確認の手順そのものを省きたい場合はこちらを使います。

ブラウザーがダウンロードしたファイルには `com.apple.quarantine` という検疫属性が
付き、Gatekeeper はこの属性が付いたアプリだけを検査します。属性を外せば OcHub は
そのまま起動します。

<Steps>

1. ダウンロードした `.dmg` を開き、**OcHub** を**アプリケーション**フォルダーへ
   ドラッグします。以下のコマンドはそこにある前提です。

2. ターミナルを開きます：<kbd>⌘</kbd> <kbd>Space</kbd> を押し、`ターミナル` と
   入力して <kbd>Return</kbd> を押します。

3. 次の 1 行をそのまま貼り付けて <kbd>Return</kbd> を押します：

   ```sh
   sudo xattr -rd com.apple.quarantine /Applications/OcHub.app
   ```

4. Mac のログインパスワードを入力して <kbd>Return</kbd> を押します。
   **入力中は画面に何も表示されません。** これはターミナルの通常の動作で、
   反応がないわけではありません。

5. OcHub を開きます。警告は表示されません。

</Steps>

`sudo` が必要なのは、この属性が個人のコピーではなくインストール済みのアプリ本体に
付いているためです。`-r` はアプリバンドルの中身にも同じ処理を適用します。
何も出力されなければ成功です。

<Aside type="caution" title="自分でダウンロードしたアプリにだけ実行してください">

検疫フラグを外すことは、そのアプリに対する macOS の安全確認を実際に無効化することを
意味します。OcHub に対してのみ、上記の正確なパスでのみ、そして OcHub の公式リリース
ページから DMG をダウンロードした場合にのみ実行してください。自分で取りに行っていない
ソフトウェアについて、他人から渡された `xattr` コマンドを貼り付けてはいけません。

</Aside>

Homebrew でインストールする場合は、最初から検疫フラグを付けずに導入できます：

```sh
brew install --cask --no-quarantine ochub-team/tap/ochub
```

OcHub 内部からインストールした更新に検疫フラグが付くことはないため、
どちらの方法もリリースごとに繰り返す作業ではなく一度きりの手順です。

Windows SmartScreen も同じ理由で警告を出すことがあります。

## 更新

OcHub は起動直後に一度、その後は 1 日 1 回新しいリリースを確認し、
**設定 → 情報 → 更新を確認**からアプリを離れずにインストールできます。
同じグループ内のトグルで確認を無効にできます。

ダウンロードされたパッケージはバイナリに埋め込まれた署名鍵で検証され、
実行中のバージョンより新しくないバージョンは拒否されます。そのため更新経路を使って
未署名のコードを配信したり、インストールを巻き戻したりすることはできません。

次の 2 つのインストール方法は確認のみで、自動更新は行いません。
自己更新するとそれを管理しているシステムと衝突するためです：

| インストール方法 | アプリ内更新 |
| --- | --- |
| macOS `.dmg`、Windows インストーラー、Linux AppImage | 対応 |
| Debian パッケージ | 非対応 — `apt` を使用し、dpkg の記録を正確に保つため |
| Windows ポータブル ZIP | 非対応 — 再実行するインストーラーが存在しないため |

この 2 つは設定画面の行に理由を表示し、リリースページへのリンクを示します。
