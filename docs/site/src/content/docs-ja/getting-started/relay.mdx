モデルプロバイダーモードではツールを OcHub のローカルゲートウェイへ向け、OcHub が現在の上流へ
リクエストを送ります。ツール設定を何度も書き換えずに上流を切り替え、プロトコル変換、
モデルマッピング、使用量記録を一元化できます。

<OcHubAppFigure locale="ja" screen="providers" />

## モデルプロバイダーを使う場面

- 複数ツールで同じ上流を共有する。
- クライアントと上流で API インターフェースが異なる。
- モデル別名、推論強度の変換、使用量集計、予備上流が必要。

1 つのツールへ 1 つのアドレスを設定するだけなら、
[直接接続](/ja/getting-started/direct-connection)の方が手順は少なくなります。

## モデルプロバイダーを作成する

<Steps>

1. **モデルプロバイダーを開きます。** API キーを含む互換設定がすでにある場合は、
   **既存設定からインポート**を先に試します。

2. **モデルプロバイダーを追加します。** 名前、上流 API の基点、アクセスキーを入力します。
   基点に `/v1` は含めないでください。OcHub がインターフェースごとのパス
   （`/v1/messages` など）を自動で付けます。

3. **インターフェースを検出します。** **検出**で Anthropic Messages、OpenAI Chat、
   OpenAI Responses を確認します。失敗した場合は上流資料に記載されたものだけを
   手動で有効にします。

4. **最初はシンプルにします。** デフォルトモデル、モデル例外、カスタム推論予算は
   空のままにします。

5. **保存してカードを確認します。** 保存前はエディターの**HTTP 遅延テスト**で
   到達性を確認でき、保存後はカードのインターフェースタグ、モデル数、
   オン／オフ状態を確認します。到達可能でも認証や実モデルのリクエストが
   成功するとは限りません。

6. **アプリページで切り替えます。** 対象アプリのページ（Codex、Claude Code など）
   を開き、**モデルプロバイダーモード**にあるモデルプロバイダーの**切り替え**を選びます。
   切り替えると、そのプロバイダーに「使用中」が表示され、実設定が
   ローカルゲートウェイを指すようになります。

</Steps>

## モデルプロバイダーを切り替える

以後の切り替えも同じアプリページで行います。

1. 対象アプリページの「モデルプロバイダーモード」（適用後は「現在のモデルプロバイダー」）で
   有効なモデルプロバイダーを選びます。
2. 以後の切り替えはツール設定を書き直さず、ローカルルートだけを更新します。
3. 「現在のモデルプロバイダー」には使用中のプロバイダーと、その既定モデルまたは
   マッピング数が表示されます。

## リクエスト経路を確認する

- 対象 CLI から短いリクエストを送ります。
- **使用量 → リクエストログ**で、データソースがモデルプロバイダーの項目を探します。
- リクエストモデル、課金モデル、プロバイダー、状態、レイテンシーを確認します。

接続できない場合は、OcHub が動作中であることと、モデルプロバイダーが有効であることを
最初に確認します。

## 別のローカルツールを接続する

**その他のツールを接続**にはループバック URL とローカルキーが表示されます。
OpenAI Chat 対応のローカルクライアントで利用できます。

<Aside type="note" title="ローカルキーは上流キーではありません">

このキーは OcHub がローカルで生成・検証します。別の PC や上流サービスでは使えません。
ループバックの待受をインターネットへ公開しないでください。

</Aside>

## 切断と直接接続への復帰

- アプリの接続ページでそのモデルプロバイダーを指す接続を削除すると、関連を解除できます。
- 使用中のモデルプロバイダーは削除できません。ダイアログに対象アプリが表示されるので、
  先にそれらのアプリを別のプロバイダーまたは直接接続へ切り替えます。
- 使用中のモデルプロバイダーを無効にすると、対象ツールのリクエストは直ちに失敗します。
  無効にする前に対象アプリを切り替えてください。
- 直接接続へ戻すには、アプリページで直接接続を選んで切り替えます。

モデルマッピング、インターフェース例外、予備上流の運用は
[ルーティング実践](/ja/advanced/routing-recipes)を参照してください。
