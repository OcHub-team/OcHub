OcHub の基本操作はシンプルです。AI ツールを選び、プロバイダーへ**直接接続**するか、
OcHub の**ローカルゲートウェイ**を経由するかを決めます。初回はどちらか一方だけを
完了させてください。

<OcHubConnectionMap locale="ja" />

## 初回設定の完了条件

次の 3 点をすべて満たせば、最初の設定は完了です。

1. 対象アプリのページで、目的の接続が「現在」と表示される。
2. 新しく起動した CLI から実リクエストを 1 回送信できる。
3. 公式ログインまたは以前の接続へ戻す方法が分かる。

この最小フローが動くまでは、MCP、スキル、価格、同期、複雑なルーティングを設定しないでください。

## 始める前に

- cc-switch を終了し、2 つのアプリが同じツール設定へ同時に書き込まないようにします。
- `~/.claude` や `~/.codex` など、対象ツールの設定ディレクトリをバックアップします。
- 利用する API エンドポイントとキーを用意します。ツール自身の公式ログインを使う場合、
  サードパーティーのキーは不要です。

cc-switch を長く使用してきた場合は、初回起動時にインポートするか決める前に
[移行ガイド](/ja/guides/migration)を確認してください。

<Aside type="note" title="OcHub が変更するもの">

OcHub 自身のデータは `~/.ochub/` に保存されます。**ツールに追加**、**切り替え**、
**アプリへ同期**を実行すると、対応する AI ツールの実設定にも書き込みます。
`~/.cc-switch/` へ書き戻すことはありません。

</Aside>

## 初回起動

<Steps>

1. **ウェルカム通知を確認します。** 設定ファイルへの書き込み説明を読みます。
   cc-switch が検出されると、インポート可能な接続、MCP サーバー、スキル
   リポジトリが表示されます。

2. **移行するか決めます。** **インポートして開始**は cc-switch データを読み込みます。
   **スキップ**しても cc-switch は変更されず、後から**設定 → データとバックアップ**で
   インポートできます。

3. **管理するアプリを選びます。** **設定 → アプリとプラグイン**で必要なツールだけを
   有効にします。無効化してもデータやツール設定ファイルは削除されません。

4. **アプリページを開きます。** サイドバーの「アプリ」から Claude Code、Codex、
   OpenCode、OpenClaw、Hermes、Grok Build、Claude Desktop のいずれかを選びます。

</Steps>

## 主な画面

| 領域 | 用途 |
| --- | --- |
| アプリ | ツールごとの直接接続と固有設定 |
| MCP サーバー | MCP 設定を一元保存し、対応ツールへ同期 |
| スキル | 再利用可能なスキルの検索、インストール、更新、配布 |
| 使用量 | トークン、コスト、キャッシュ、レイテンシー、個別リクエスト |
| セッション | ローカル CLI の会話履歴 |
| 高度なツール | CLI、バックアップ、環境変数、ツール固有ファイル |
| モデルプロバイダー | ゲートウェイ上流、モデルマッピング、バックアップ切り替え |
| テーマ / 設定 | 外観、アプリ動作、データ、リモート同期 |

## 接続方法を選ぶ

| 目的 | 推奨方法 |
| --- | --- |
| 1 つのツールへ 1 つの API を設定 | [直接接続](/ja/getting-started/direct-connection) |
| ツール自身のアカウントログインを継続 | 直接接続内の「公式ログイン」 |
| 複数ツールで同じ上流を共有 | [モデルプロバイダー](/ja/getting-started/relay) |
| モデル名変更、プロトコル変換、予備上流への切り替え | [モデルプロバイダー](/ja/getting-started/relay) |

最初は直接接続がおすすめです。対象 CLI から実際のリクエストが成功してから、MCP、
スキル、複雑なルーティングを追加します。
