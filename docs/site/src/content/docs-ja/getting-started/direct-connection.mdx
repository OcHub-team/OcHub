直接接続では、接続の設定を指定した AI ツールへ書き込み、そのツールが OcHub
ゲートウェイを経由せずにプロバイダーへ接続します。初回利用に最も適した方法です。

<OcHubAppFigure locale="ja" screen="editor" />

## 直接接続を使う場面

- OcHub を初めて設定する。
- 1 つのツールから 1 つのプロバイダーへ直接接続する。
- ツール自身の公式アカウントログインを使い続ける。

複数ツールでルーティング、モデル別名、予備の上流を共有する場合は、
[モデルプロバイダー](/ja/getting-started/relay)を使用します。

## 接続を追加する

<Steps>

1. **アプリを選びます。** サイドバーの「アプリ」から設定するツールを開きます。

2. **エディターを開きます。** **接続を追加**を選びます。既存のローカル設定が検出済み
   なら、重複を作らずその項目を編集できます。

3. **開始点を選びます。** 適切なプリセットがあれば使用し、なければ空の設定から始めます。
   「仕事用アカウント」「予備エンドポイント」など用途が分かる名前を付けます。

4. **接続情報を入力します。** プロバイダーの資料に従って API アドレスとキーを入力します。
   モデルプロバイダーのエディターは `/v1` を処理しますが、直接接続では生成ファイルのプレビューを
   基準にしてください。

5. **利用可能なチェックを実行します。** **URL をテスト**、**モデルを取得**、
   **残高を確認**を順に試します。URL テスト成功は HTTP 応答があったという意味で、
   キーやモデルの有効性までは保証しません。

6. **書き込みプレビューを確認します。** **書き込むファイル**を展開し、保存先と重要
   フィールドを確認します。空の場合は名前と接続情報を補完します。

7. **保存します。** 保存は接続を OcHub に追加します。ツールへ即時反映するかは、
   そのアプリページに表示される操作によって異なります。

</Steps>

<Aside type="caution" title="実際のキーを文書やスクリーンショットへ載せない">

API キーはローカル設定だけに保存してください。ログやプレビューを共有する前に、キー、
アクセストークン、認証パラメーター付き URL をプレースホルダーへ置き換えます。

</Aside>

## 追加と切り替え

| 操作 | 意味 |
| --- | --- |
| ツールに追加 | 現在の接続を変えずにツール設定へ追加 |
| 切り替え | 書き込みまたは選択し、現在の接続にする |
| インポート | Cherry Studio のように対象アプリを開き、そこでインポートを確認する |
| ツールから削除 | OcHub のデータを残し、ツール側だけから削除 |
| 削除 | OcHub から完全に削除。元に戻せません |

切り替えに成功すると、ページ上部の「現在の接続」とカードの「現在」表示が更新されます。

## 反映を確認する

1. 設定をキャッシュした既存プロセスを避けるため、対象 CLI を終了して開き直します。
2. 短いリクエストを送ります。
3. 成功したら OcHub の**使用量**を更新し、セッションまたはリクエストを確認します。
4. 古い設定を使い続ける場合は、アプリ設定のディレクトリと実際のインストール先を
   比較します。

## 外部変更を処理する

OcHub が最後に読み込んだ後で別のプログラムが設定を変更すると、次の切り替え時に
「設定ファイルが外部で変更されました」と表示されます。

- **自分の変更を保持**：外部変更を可能な範囲でマージし、安全に保持できない項目を表示。
- **自分の変更を破棄**：OcHub の書き込みプレビューを優先。
- **キャンセル**：ファイルを書き換えず、バックアップと比較を行う。

判断できない場合はキャンセルし、元ファイルをコピーしてから再実行してください。

## 元に戻す

- 別の接続へ戻すには、そのカードで**切り替え**を選びます。
- ツール自身のログインへ戻すには、公式ログインの接続へ切り替えます。
- 管理を停止するには**設定 → アプリとプラグイン**で無効化します。現在の実設定は
  自動的には変更されません。
