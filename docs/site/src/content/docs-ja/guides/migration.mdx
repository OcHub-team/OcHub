OcHub は cc-switch の一度きりの読み取り専用インポートに対応します。`~/.cc-switch/` を
読み、認識できるデータを OcHub へコピーします。cc-switch 側を変更・削除しません。

データのインポートとツール実設定の切り替えは別の操作です。OcHub で「ツールに追加」または
「切り替え」を実行するまで、対象 CLI の現在設定は維持されます。

## インポートできるもの

| 移行元 | 既定ファイル | 説明 |
| --- | --- | --- |
| SQLite データベース | `~/.cc-switch/cc-switch.db` | cc-switch v3.x 以降。最も完全 |
| 旧 JSON | `~/.cc-switch/config.json` | 以前のリリース |

両方ある場合はデータベースを優先します。認識可能なプロバイダーとエンドポイント、MCP、
スキルとリポジトリ、設定、モデル価格、使用量履歴、プロファイルなどを移せます。旧 JSON は
実際に含まれる対応設定を移します。

次は対象外です。

- cc-switch が保持するツール実設定の引き継ぎバックアップ。
- 一時的な速度チェックログ。
- OcHub が認識しないアプリ種別やフィールド。
- cc-switch のデータディレクトリ転送情報。

移行後はファイルサイズだけでなく、プロバイダー、MCP、スキル、価格、重要設定を個別確認します。

## 移行前の準備

1. cc-switch を完全に終了します。
2. Claude Code、Codex、OpenCode など対象ツールを終了します。
3. `~/.cc-switch/` 全体をバックアップします。
4. OcHub にデータがある場合、**高度なツール → データベースバックアップ**でスナップショットを
   作ります。
5. 各ツールで動作するプロバイダーとモデルを記録します。
6. 未確認データをリモートへ送らないよう WebDAV / S3 自動同期を一時停止します。

<Aside type="caution" title="2 つの管理ツールで同時に書き込まない">

インポート自体は cc-switch を読むだけですが、その後の切り替えは実設定を書き換えます。
検証中は cc-switch を終了したままにしてください。

</Aside>

## 初回起動時にインポートする

<Steps>

1. **検出結果を確認します。** パス、プロバイダー数、MCP 数を確認します。

2. **インポートして開始を選びます。** 確定するまでコピーされません。スキップしても
   cc-switch は変更されません。

3. **完了を待ちます。** インポート中に対象 CLI を起動したり OcHub を閉じたりしません。

4. **アプリページを確認します。** 各プロバイダーが正しいアプリに表示されることを確認します。

5. **先に OcHub 内のデータを確認します。** 名前、アドレス、モデル、MCP、スキルを確認してから
   実ツールを切り替えます。

</Steps>

初回にスキップしても、後から手動インポートできます。

## 既存の OcHub へ再インポートする

**設定 → データとバックアップ → cc-switch からインポート**を開きます。

1. 検出パスと件数を確認します。
2. インポートを選び、上書き警告を読みます。
3. 既存プロバイダーがあれば先にデータベーススナップショットを作ります。
4. 同じ ID は cc-switch 側で置き換え、異なる ID はマージします。
5. 完了後にインポート行数が表示されます。

初回にスキップした、後から既定場所へデータを戻した、cc-switch で最後の整理をした場合に
利用します。長期の双方向同期には使わないでください。

## 競合ルール

- **同じ ID**：cc-switch 側が OcHub 側を置き換えます。
- **異なる ID で同じ名前**：両方残る場合があり、手動整理が必要です。
- **同じ ID の組み込み価格**：インポートしたカスタム価格が置き換える場合があります。
- **既存プロバイダーがある OcHub**：先にスナップショットを作ります。
- **未知の項目や新しいテーブル**：対応内容は継続し、未知部分はスキップまたは警告します。

OcHub 側ですでに同じプロバイダーを編集した場合、別 ID に複製するかバックアップしてください。

## 移行後の確認

### 1. プロバイダー

- 正しいアプリにある。
- Base URL に重複した `/v1` や完全なリクエストパスがない。
- キーと認証方式が一致。
- インポート済みと現在を混同していない。
- プレビューがツール固有項目を保持。

### 2. MCP とスキル

- MCP JSON が完全なオブジェクトで、対象アプリが正しい。
- インポートだけでは実設定へ同期されないため、確認後に同期。
- スキルリポジトリが更新でき、インストール元を認識。
- 古いリポジトリは削除前に無効化して様子を見る。

### 3. 価格と使用量

- モデル ID がログの課金モデルと一致。
- 入力、出力、キャッシュ読み書き価格の列が正しい。
- デフォルト倍率と課金元が現在の構成に合う。
- 履歴コストの計算に必要なトークンとモデル情報がある。

### 4. 設定と同期

- データディレクトリが `~/.ochub/` または意図した場所。
- 旧転送設定で `~/.cc-switch/` を指していない。
- WebDAV / S3、プロファイル、リモートディレクトリが正しい。
- 検証後に自動同期を再開し、確認済みスナップショットを手動アップロード。

### 5. 実リクエスト

1. 1 つのアプリを試験対象にします。
2. 実設定ディレクトリをバックアップします。
3. 検証済みプロバイダーへ切り替えます。
4. CLI を再起動して短いリクエストを送ります。
5. モデル、状態、使用量を確認します。
6. 成功してから次のアプリへ進みます。

## 問題がある場合のロールバック

1 ツールだけなら切り替えを止め、既知の公式ログインまたはプロバイダーへ戻し、必要なら
ディレクトリバックアップを復元します。

全体のインポートが違う場合：

1. 対象 CLI を終了します。
2. **高度なツール → データベースバックアップ**を開きます。
3. インポート前の自動スナップショットを選びます。
4. 復元します。現在のデータベースも先に安全バックアップされます。
5. 再起動して確認します。

データベース復元は、その後の切り替えで変更済みの各ツール実設定を自動復元しません。
ディレクトリバックアップも保持してください。

## cc-switch を停止できる時点

- 必要なプロバイダーを OcHub で編集・プレビューできる。
- 直接接続と必要なリレーで実リクエストが成功。
- MCP とスキルが対象へ同期済み。
- セッション、使用量、価格が正しい。
- ローカルデータベースバックアップがある。
- 検証済みリモートスナップショットをアップロード済み。

条件を満たしても、`~/.cc-switch/` はしばらくアーカイブしてから削除してください。
[データ、バックアップ、同期](/ja/advanced/data-sync)も参照してください。
