OcHub 的供应商、MCP、技能仓库、设置和部分用量数据保存在本地数据库。远端同步上传的是
数据库和托管技能快照，不等同于同步每个 AI 工具的全部实时配置目录。

## 本地数据目录

默认数据目录是 `~/.ochub/`，其中包含数据库、备份和托管技能。可以从
**设置 → 数据与备份**更改目录。

更改后建议重启应用，让数据库和后台服务从同一位置重新加载。恢复默认位置只会清除路径
覆盖，不会自动合并两个目录的数据。

## 自动备份

在“数据与备份”中设置：

- **自动备份间隔**：每隔多长时间创建一次本地数据库快照。
- **备份保留数量**：超过数量的旧备份会被自动清理。

高频修改供应商或同步设置时，使用较短间隔；磁盘空间有限时减少保留数量。

## 手动备份与恢复

打开**高级工具 → 数据库备份**：

1. 点击“创建备份”生成当前数据库快照。
2. 可以重命名备份，标记用途和日期。
3. 恢复前确认备份名称；OcHub 会先为当前数据库再创建一份安全备份。
4. 恢复完成后重启应用，检查供应商、MCP、技能和设置。

删除备份不可撤销。至少保留一份不在本机数据目录内的已验证副本。

## 选择远端目标

OcHub 支持 WebDAV 和 S3 兼容存储。一个配置应明确使用一个同步目标；检测到两者同时启用
时，页面会按最近一次同步推断当前目标，保存设置前应重新确认。

<Tabs>

<TabItem label="WebDAV">

需要填写 WebDAV 地址、用户名和密码。地址必须以 `http://` 或 `https://` 开头。

</TabItem>

<TabItem label="S3 / R2">

需要填写 Access Key ID、Secret Access Key、区域和 Bucket。AWS S3 可以留空自定义
Endpoint；Cloudflare R2 通常使用它提供的 Endpoint，并把区域设为 `auto`。

</TabItem>

</Tabs>

两种目标都可以设置：

- **配置档**：同一远端目录下的逻辑名称，默认 `default`。
- **远端目录**：同步快照的根目录，默认 `ochub-sync`。

不同设备要共享数据时，目标、远端目录和配置档必须一致。

## 测试、保存与上传

1. 填写连接信息。
2. 点击“测试”确认连接；测试不会保存刚填写的内容。
3. 点击页面底部“保存”。
4. 保存成功后执行“上传本地快照”。
5. 检查状态区域中的最近同步时间和最近错误。

开启“自动同步”后，数据库变化会排队上传。它不是实时双向合并；多台设备同时修改可能让
后上传的快照覆盖先前版本。

## 从远端恢复

“从远端还原”会下载快照并覆盖当前本地数据库。执行前：

1. 停止在其他设备上继续修改。
2. 核对同步目标、配置档和最近同步时间。
3. 确认还原操作。
4. OcHub 会先备份当前本地数据，再覆盖数据库。
5. 完成后重启应用并抽查关键配置。

如果远端恢复失败且本地安全备份已经创建，先解决连接问题，不要重复执行多次恢复。

## 从 cc-switch 再次导入

在**设置 → 数据与备份 → 从 cc-switch 导入**可以重新执行迁移。同 ID 记录会被 cc-switch
版本替换；导入前 OcHub 会创建数据库快照。该过程只读 `~/.cc-switch/`，不会修改
cc-switch 自身。

首次迁移、冲突规则、分批验收和回退步骤见[从 cc-switch 迁移](/zh/guides/migration)。
