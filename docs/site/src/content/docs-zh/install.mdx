每个版本标签都在对应的原生 GitHub 托管 runner 上构建。

## Homebrew（macOS）

Homebrew 会自动选择 Apple Silicon 或 Intel 版本：

```sh
brew install --cask ochub-team/tap/ochub
```

升级或卸载：

```sh
brew upgrade --cask ochub-team/tap/ochub
brew uninstall --cask ochub
```

Cask 维护在
[`OcHub-team/homebrew-tap`](https://github.com/OcHub-team/homebrew-tap)
仓库中，下载的是每个 GitHub Release 发布的同一个 DMG。

## 直接下载

| 平台 | 发布文件 |
| --- | --- |
| macOS Apple Silicon | ARM64 `.dmg` |
| macOS Intel | x64 `.dmg` |
| Windows 10/11 x64 | NSIS 安装包和便携版 `.zip` |
| Linux x64 | AppImage 和 Debian `.deb` |

发布内容还包含 `SHA256SUMS` 和 GitHub 制品证明。校验已下载的文件：

```sh
sha256sum -c SHA256SUMS --ignore-missing
gh attestation verify <downloaded-file> --repo OcHub-team/OcHub
```

## macOS：首次启动时授权

OcHub 使用自签名证书签名，没有经过 Apple 公证。Gatekeeper 只信任能一路追溯到
Apple 根证书的证书，自签名证书追溯不到，所以 macOS 会要求你授权一次。这对 OcHub
来说是正常现象，不代表你下载的文件有问题。

### 方式一：在系统设置里授权

<Steps>

1. 打开 OcHub，macOS 提示无法验证开发者。

2. 前往**系统设置 › 隐私与安全性**，滚动到"安全性"，点击**仍要打开**。

</Steps>

在 macOS 15 及更高版本上，右键点击应用的老办法已经失效——只能走系统设置这条路。

### 方式二：在终端里清除隔离标记

如果**仍要打开**这个按钮压根没出现、macOS 提示 OcHub"已损坏"，或者你不想走上面
那套弹窗流程，用这个办法。

浏览器下载的任何文件，macOS 都会打上一个叫 `com.apple.quarantine` 的隔离标记，
而 Gatekeeper 只检查带这个标记的应用。把标记去掉，OcHub 就能正常打开。

<Steps>

1. 打开下载好的 `.dmg`，把 **OcHub** 拖进**应用程序**文件夹。下面的命令默认它在那里。

2. 打开"终端"：按 <kbd>⌘</kbd> <kbd>空格</kbd>，输入 `终端`，回车。

3. 原样粘贴这一行，然后回车：

   ```sh
   sudo xattr -rd com.apple.quarantine /Applications/OcHub.app
   ```

4. 输入你的 Mac 登录密码，回车。**输密码时屏幕上不会显示任何字符**，这是终端一贯的
   行为，不是卡住了。

5. 打开 OcHub，这次不会再有任何警告。

</Steps>

需要 `sudo` 是因为这个标记记在装好的应用上，而不是记在你个人的副本上；`-r` 表示
连同应用包内部的文件一起处理。命令执行后没有任何输出，就说明成功了。

<Aside type="caution" title="只对你自己下载的应用执行">

清除隔离标记等于关掉了 macOS 对这个应用的一道真实安全检查。请只对 OcHub 执行、
只用上面这个确切的路径、并且只在你确实是从 OcHub 官方发布页下载 DMG 的情况下执行。
永远不要为一个不是你主动去下载的软件，粘贴别人给你的 `xattr` 命令。

</Aside>

如果你用 Homebrew 安装，也可以在安装时就不加隔离标记：

```sh
brew install --cask --no-quarantine ochub-team/tap/ochub
```

从 OcHub 内部安装的更新永远不会被加上隔离标记，所以以上两条路都是一次性步骤，
不需要每次发版都重复。

Windows SmartScreen 可能出于同样原因发出警告。

## 更新

OcHub 会在启动后不久检查一次新版本，之后每天检查一次，并可以从
**设置 → 关于 → 检查更新**直接安装，无需离开应用。用同一分组里的开关可以关闭检查。

下载的安装包会用编译进二进制的签名密钥校验，且不接受不比当前运行版本更新的版本，
因此更新通道无法被用来推送未签名代码，也无法把安装回滚到旧版。

有两种安装方式只做检查、不自动更新，因为自更新会和管理它们的系统冲突：

| 安装方式 | 应用内更新 |
| --- | --- |
| macOS `.dmg`、Windows 安装包、Linux AppImage | 支持 |
| Debian 包 | 不支持——请用 `apt`，以保证 dpkg 的记录准确 |
| Windows 便携版 ZIP | 不支持——没有可重新运行的安装程序 |

这两种方式会在设置行里说明原因，并给出发布页链接。
