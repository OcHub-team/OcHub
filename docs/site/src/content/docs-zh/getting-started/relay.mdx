中转模式会先把工具指向 OcHub 的本地网关，再由 OcHub 把请求发送到当前上游。这样可以
在不反复改写工具配置的情况下切换上游，并集中处理接口转换、模型映射和用量统计。

## 创建中转

<Steps>

1. **打开“中转”。** 如果本机已有带 API Key 的兼容配置，可先点“从现有配置导入”。

2. **添加中转。** 填写名称、上游 API 地址和访问密钥。API 地址不必以 `/v1` 结尾；页面会显示规范化后的请求地址。

3. **检测可用接口。** 点击“检测”，OcHub 会尝试 Anthropic Messages、OpenAI Chat 和 OpenAI Responses。自动检测失败时，按上游文档手动选择。

4. **保持简单配置。** 第一次使用先不要填写默认模型、模型例外或自定义思考预算。

5. **保存并检测连通。** 保存后点击卡片上的“检测连通”。连通正常只代表地址可达，最终仍需用真实模型请求验证。

6. **在应用页面启用。** 打开目标应用页面（如 Codex），在“中转模式”区域点击该中转的“切换”。切换成功后，工具配置会指向本地网关。

</Steps>

## 切换中转

之后的切换同样在应用页面完成：

1. 在“中转模式”区域选择一个已启用的中转。
2. 点击切换后，OcHub 只更新本地路由，不再反复改写工具配置。
3. “当前中转”会显示正在使用的上游、默认模型或模型映射数量。

## 验证请求路径

- 启动目标 CLI 并发起一条短请求。
- 在 OcHub **用量 → 请求日志**中查找来源为“中转请求”的记录。
- 打开请求详情，核对请求模型、实际计价模型、Provider、状态和延迟。

如果工具报告无法连接，先确认 OcHub 仍在运行，然后检查中转是否处于“已启用”状态。

## 让其他工具接入

“其他工具接入”区域会提供本机地址和本地密钥。任何支持 OpenAI Chat 接口的本机工具都可以
使用这组信息。

<Aside type="note" title="本地密钥不是上游密钥">

这里的密钥由 OcHub 在本机生成和验证，只用于访问本地网关，不能拿到其他电脑或上游服务中使用。
不要把本地监听地址暴露到公网。

</Aside>

## 断开与恢复

- 在中转页面的“当前连接”中选择“断开”，可以解除某个应用与中转的关系。
- 正被应用使用的中转不能直接删除；先切换或断开对应应用。
- 停用正在使用的中转会让相关工具请求立即失败，确认对话会列出受影响的应用。
- 要回到直接连接，在对应应用页面选择一个直接连接并切换。

需要模型映射、接口例外或故障转移时，继续阅读[高级功能](/zh/advanced)。
