OcHub 的核心工作很简单：选择一个 AI 工具，再决定让它**直接连接供应商**，还是先经过
OcHub 的**本地网关**。第一次使用时，先只完成其中一条路径。

<OcHubConnectionMap locale="zh" />

## 怎样算首次配置成功

同时满足下面三点，才算完成第一次配置：

1. 目标应用页面把预期连接显示为“当前连接”。
2. 重新打开的 CLI 能成功发起一条真实请求。
3. 你知道如何切回官方登录或之前使用的连接。

在这个最小闭环跑通前，先不要继续配置 MCP、技能、定价、同步或复杂路由。

## 开始前

- 退出正在运行的 cc-switch，避免两个程序同时写入工具配置。
- 备份目标工具的配置目录，例如 `~/.claude` 或 `~/.codex`。
- 准备要使用的 API 地址与密钥；如果使用工具自身的官方登录，则不需要第三方密钥。

已经长期使用 cc-switch 时，建议先浏览[迁移教程](/zh/guides/migration)，再决定首次启动提示
中是否导入。

<Aside type="note" title="OcHub 会修改什么">

OcHub 自己的数据保存在 `~/.ochub/`。当你执行“添加到工具”“切换”或“同步到应用”时，
它还会写入对应 AI 工具的实时配置。OcHub 不会回写 `~/.cc-switch/`。

</Aside>

## 首次启动

<Steps>

1. **确认欢迎提示。** 阅读配置写入说明；如果检测到 cc-switch，OcHub 会列出可导入的连接、MCP 服务器和技能仓库。

2. **决定是否迁移。** 选择“导入并开始”会读取 cc-switch 数据；选择“跳过”不会删除或修改 cc-switch，之后仍可从**设置 → 数据与备份**重新导入。

3. **选择要管理的应用。** 在**设置 → 应用与插件**中保留需要的工具。停用应用只会把它从侧栏和系统菜单移除，不会删除已有数据或改动它的配置文件。

4. **回到应用页面。** 从左侧“应用”分组选择 Claude Code、Codex、OpenCode、OpenClaw、Hermes 或 Claude Desktop。

</Steps>

## 认识主界面

| 区域 | 用途 |
| --- | --- |
| 应用 | 管理每个 AI 工具的直接连接和应用专属设置 |
| MCP 服务器 | 统一保存 MCP 配置并同步到多个工具 |
| 技能 | 搜索、安装、更新并分发可复用技能 |
| 用量 | 查看 Token、成本、缓存、延迟和请求明细 |
| 会话 | 浏览本机 CLI 的会话记录 |
| 高级工具 | 处理 CLI、备份、环境变量和工具专属配置 |
| 模型供应商 | 管理本地网关上游、模型映射和故障转移 |
| 主题 / 设置 | 管理外观、应用行为、数据和远端同步 |

## 选择连接方式

| 你的目标 | 建议方式 |
| --- | --- |
| 给一个工具配置一个 API 地址 | [直接连接](/zh/getting-started/direct-connection) |
| 沿用工具自身的账号登录 | 直接连接中的“官方登录” |
| 多个工具共用同一个上游 | [模型供应商模式](/zh/getting-started/relay) |
| 需要模型改名、接口转换或故障转移 | [模型供应商模式](/zh/getting-started/relay) |

第一次使用建议先完成直接连接。确认目标 CLI 能正常发起一次请求后，再配置 MCP、技能或
更复杂的转发规则。
