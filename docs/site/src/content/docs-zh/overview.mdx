OcHub 是面向 AI 编程工具的原生桌面控制中心。切换模型供应商、管理共享能力、运行本地网关，
都在一个地方完成——不依赖浏览器外壳，也不用 webview。

## 先建立一个简单模型

可以把 OcHub 理解成三层：

1. **应用**是你真正运行的工具，例如 Claude Code 或 Codex。
2. **连接**描述某个应用如何鉴权并访问 API。
3. **模型供应商**是可选的共享上游，位于 OcHub 本地网关之后。

先从“一个应用 + 一个直接连接”开始。只有需要共享路由、接口转换或故障转移时，才增加
本地网关这一层。

## OcHub 管理什么

OcHub 管理 **Claude Code、Claude Desktop、Codex、Grok Build、OpenCode、OpenClaw 和 Hermes**。

| 领域 | 能力 |
| --- | --- |
| 连接 | 发现、导入、编辑、切换和测试直连 API |
| 模型供应商 | 让受支持的客户端经由本地网关路由，支持模型别名、推理映射、接口候选重试、备用模型供应商切换、健康检查和用量统计 |
| 共享工具 | 跨受支持客户端管理 MCP 服务器和可复用技能 |
| 远程节点 | 通过 SSH 切换 WSL、开发机和无桌面服务器上的连接，并管理远端网关 |
| 运维 | 浏览会话、查看用量、配置同步、管理应用行为 |
| 迁移 | 从兼容的 cc-switch 数据库一次性只读导入 |

## 它如何触碰你的配置

OcHub 拥有 `~/.ochub/`，绝不回写 `~/.cc-switch/`。但它确实会更新你明确指定要管理的
那些工具的实时配置目录。

:::caution
在 OcHub 里切换连接之前请先退出 cc-switch——两者写入同一批工具配置目录，同时运行
可能导致写入交错。
:::

:::note
OcHub 正处于活跃的预发布开发阶段。试用早期版本前请备份重要的工具配置。
:::
