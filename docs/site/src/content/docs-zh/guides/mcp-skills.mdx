MCP 服务器与技能都可以分发到多个应用，但同步方式不同：

- MCP 由 OcHub 保存 JSON 配置，再统一写入已启用的应用。
- 技能通过 skills CLI 安装，并按技能卡片上的应用开关分发。

## 应用支持范围

| 应用 | MCP | 技能 |
| --- | --- | --- |
| Claude Code | 支持 | 支持 |
| Claude Desktop | 不支持 | 不支持 |
| Codex | 支持 | 支持 |
| Grok Build | 支持 | 不支持 |
| OpenCode | 支持 | 支持 |
| OpenClaw | 不支持 | 不支持 |
| Hermes | 支持 | 支持 |

应用开关只会显示该工具真实支持的能力。Claude Desktop 与 OpenClaw 的原生扩展配置不由这两个
页面管理。

## MCP：导入现有配置

<Steps>

1. 打开**MCP 服务器**。
2. 点击“从应用导入”。
3. OcHub 扫描受支持应用的现有 MCP 配置，只新增尚未存在的服务器。
4. 检查每张卡片的应用列表，再点击“同步到应用”。

</Steps>

导入不会自动删除应用里的未知配置。出现部分失败时，状态栏会列出失败项。

## MCP：手动新增

点击“新增”，填写名称、可选描述和服务器 JSON。

stdio 服务器示例：

```json
{
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem"]
}
```

SSE 服务器示例：

```json
{
  "type": "sse",
  "url": "https://example.com/sse"
}
```

保存前至少选择一个目标应用。JSON 必须是对象，命令、参数、环境变量等字段会按目标工具的
格式转换。

<Aside type="caution" title="确认命令来源">

stdio MCP 会在本机执行 `command`。只同步你信任的包和命令，并在终端中确认相应命令位于
`PATH`。不要直接运行来源不明的配置。

</Aside>

## MCP：启用与同步

1. 在卡片上打开或关闭各应用开关。
2. 完成多项调整后点击“同步到应用”。
3. 重启目标 CLI，让它重新读取 MCP 配置。
4. 如果目标应用没有出现服务器，检查应用是否已启用、配置目录是否正确，以及服务器 JSON 是否符合该工具支持的传输方式。

删除 OcHub 中的 MCP 服务器后，再次同步会更新由 OcHub 管理的目标配置。删除不可撤销，
操作前可先复制 JSON。

## 技能：从市场安装

<Steps>

1. 打开**技能 → 发现**，选择“市场搜索”。
2. 输入用途关键词，例如 `pdf`、`frontend` 或 `testing`。
3. 在“安装到”中选择目标应用。
4. 点击技能卡片上的“安装”。
5. 回到“已安装”，确认技能及其来源。

</Steps>

## 技能：从仓库发现

1. 在“发现”页切换到“仓库浏览”。
2. 输入 `owner/repo`、`owner/repo@branch` 或完整 GitHub 链接。
3. 添加仓库后点击“刷新发现”。
4. 从发现结果安装需要的技能。

停用仓库后，它不再参与发现，但已经安装的技能不会被删除；删除仓库同样不会卸载技能。

## 更新和分发技能

- 点击“检查更新”比较本地与远程版本。
- 有更新时可逐个更新或使用“全部更新”。
- 卡片上的应用开关控制技能同步到哪些已启用应用。
- “目录”打开本地安装位置，“仓库”打开远程来源。
- 卸载会让 skills CLI 从已启用应用中移除该技能。

市场搜索或更新需要网络。如果提示 skills CLI 不可用，前往
[高级功能 → CLI 工具维护](/zh/advanced#cli-工具维护)检查安装与 `PATH`。

Claude 的插件集成、Codex 配置目录以及 OpenCode / Hermes 的应用差异见
[Claude 专项教程](/zh/guides/claude)、[Codex 专项教程](/zh/guides/codex)和
[其他工具专项教程](/zh/guides/open-tools)。
