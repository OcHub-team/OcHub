## 选择账号与模型来源

连接页分别管理账号身份和模型请求去向。第三方 API Key 只填写在模型供应商处；选择“手动配置”时才在连接中填写地址和密钥。

| 模型来源 | 账号 | 行为 |
| --- | --- | --- |
| 官方 | ChatGPT | 使用真实账号和官方端点 |
| 模型供应商 | ChatGPT | 保留真实登录，经本地 OcHub 路由到第三方；上游使用供应商 API Key |
| 模型供应商 | 不使用账号 | 使用 OcHub 签发的 API Key 接入供应商 |
| 手动配置 | ChatGPT | 自定义地址与独立 API Key；不会因此获得实验性上下文管理 |
| 手动配置 | 不使用账号 | 直接使用第三方 API |

真实账号登录仍在 Codex 中完成。选择 ChatGPT 不代表已完成登录或验证订阅。

1. 在**模型供应商**中填写地址、API Key、协议，选择模型并保存。
2. 在 **Codex → 添加连接**选择模型来源和供应商。
3. 账号选择 **ChatGPT**，使用已有真实登录；没有账号则选择**不使用账号**。
4. 选择模型，上下文管理保留**自动**。
5. 检查配置预览，保存连接并切换，然后重新打开 Codex 会话。

**保存**仅保存 Codex 连接草稿，不改写当前连接文件。**保存并启用**保存后执行切换，保留外部配置修改。**检查配置**仅检查本地配置条件，不发送推理请求，也不验证订阅或服务端能力。远程工作区需要支持草稿操作的新版本节点。

**高级设置**中的虚拟登录仅用于兼容不具备真实账号的客户端，不提供订阅或官方额度。不要与真实账号同时使用；OcHub 会拒绝用虚拟登录覆盖真实凭据。

## 上下文管理的状态

实验性上下文管理与普通压缩不是同一项能力。

| 选择 | 配置行为 |
| --- | --- |
| 自动 | 官方默认端点采用 Codex 的实验性入口；第三方与 OcHub 路由不自动开启 |
| 开启 | ChatGPT + OcHub 显式启用 Token Budget 与 History / Notes，需要兼容的分发服务 |
| 关闭 | 写入关闭意图，后续供应商地址注入不会重新开启 |

“待 Codex 验证”表示只完成配置，不表示后端可用性已验证。独立 API Key 连接不启用此账号扩展。

分发服务支持 History / Notes 时，选择 **ChatGPT**，绑定只有一个 Responses 通道的供应商，上下文管理选择**开启**。OcHub 保留真实登录，显式写入 `[features.token_budget] enabled = true` 与 `use_history_notes_extension = true`，无需修改 ID Token 的套餐声明。Codex 仍需包含对应扩展、已知模型上下文长度，并满足管理策略。远程控制继续使用官方 `chatgpt_base_url`，该地址不会被此配置改写。保存不会验证上游能力或官方配对。

OcHub 转发十个 History / Notes 操作，包含 `thread_hint`。请求从本地 `/backend-api/codex/alpha/` 转发到供应商 Responses 端点同级的 `alpha/` 路径，不要求 model 字段，保留加密参数、结果和上游状态；真实 OAuth 与账号头不会传给供应商。多个启用通道或非 Responses 通道会被拒绝，笔记写入不会换通道重试。

分发服务负责历史采集、存储、查询、笔记、用户归属校验和会话到上游账号的持久绑定。已有会话不要切换供应商。网关**自动**模式保持保守，不自动启用。0.5.16 曾把压缩转发误写为完整历史支持，该说法不成立。

历史会话请持续使用同一个分发 API Key；更换 Key 后请新建会话。

### Codex 的自动启用条件

以下条件来自对应 Codex 源码的 `apply_experimental_context`，仅适用于该实验性自动入口：

- `[features.context_management] experimental_mode = true`。
- Provider 的 `name` 精确为 `OpenAI`。
- `base_url` 留空，或去除尾部斜线后以 `/backend-api/codex` 结尾。
- `requires_openai_auth = true`。
- Provider 不含 `env_key`、`experimental_bearer_token`、`auth`、`aws`，空字符串也算存在。
- 认证模式为 `Chatgpt`，读取到的套餐为 Plus、Pro 或 ProLite。
- Token Budget 可启用，且没有被托管策略固定关闭。

通过检查会启用 Token Budget 与 `use_history_notes_extension`。实际使用还要求客户端安装 History / Notes 扩展、知道模型上下文窗口，并具备可工作的历史写入、检索与笔记服务。仅手动设置 Token Budget 或使用模型默认预算配置，是其他启用路径，不能与这里的套餐限制混为一谈。

### History / Notes 与压缩

完整历史能力依赖 `alpha/history/v2/*` 和 `alpha/notes/v2/*`，包括 `thread_hint`、历史检索和笔记读写。OcHub 提供转发，具体服务与历史采集由分发后端实现；转发不代表已验证官方历史服务。

`/responses/compact` 只是远程压缩接口。OcHub 支持转发 `/v1/responses/compact` 与 Codex 后端形态的压缩请求，上游仍必须支持该接口。Chat 或 Messages 转换不能代替远程压缩。

## 声明模型能力

在**模型供应商 → 编辑 → 模型**中，点击某个已选择模型的**模型能力**。

| 字段 | 语义 |
| --- | --- |
| Responses Lite：自动 | 未声明，保守关闭；不继承同名官方模型的 Lite 能力 |
| Responses Lite：支持 | 在生成的 Codex 模型目录中声明 `use_responses_lite = true` |
| Responses Lite：不支持 | 明确关闭 |
| 远程压缩：自动 | 未验证，由实际 Responses 请求决定是否可用 |
| 远程压缩：支持 | 用户声明上游支持；仍需实际请求验证 |
| 远程压缩：不支持 | 网关明确拒绝该模型的压缩请求 |
| 上下文窗口 | 正整数；留空使用目录默认值 |

界面标注**用户声明 · 未验证**。当前模型列表获取不构成 Lite、压缩或历史服务验证。能力按供应商及上游模型保存，同名模型在不同供应商之间不共享声明；映射别名使用对应上游模型的声明。

Lite 是 Responses 的请求行为，不是第三种认证方式，也不是上下文管理的先决条件。Lite 请求必须走原生 Responses 通道，不会降级到 Chat / Messages 转换。请只为实际支持 Lite 语义的上游声明支持。

## 连接路由与凭据

新生成的真实登录连接地址形如：

```text
http://127.0.0.1:4180/connection/rd-…/backend-api/codex
```

连接地址中的随机网关密钥绑定供应商路由；真实账号令牌仍来自 `auth.json`。OcHub 向上游发送供应商 API Key，并移除本地路由凭据。不同供应商的连接不再依赖同一个全局 OAuth 路由绑定。

该 URL 含本地访问凭据，不应公开分享。服务仍只监听本机。路由密钥不验证 ChatGPT 订阅；账号有效性由 Codex 与对应账号服务判断。停用密钥会拒绝该连接。

旧的不带 `/connection/…` 的地址仍兼容手动配置的全局 OAuth 绑定；重新保存并启用连接可迁移到独立路由。

## 历史、MCP 与技能

“统一 Codex 会话历史”与“迁入既有 Codex 会话”管理本地会话文件，与实验性 History / Notes 后端无关。调整历史位置前退出 Codex 并保留备份。

MCP 和技能可在相应页面启用 Codex 并同步；配置目录改变后需重新同步并重启会话。更多内容见 [Codex 进阶](/zh/codex/advanced) 和 [模型供应商](/zh/getting-started/relay)。
